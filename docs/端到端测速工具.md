# 完整 observation-to-action 测速工具

当前为**实现与 CPU 行为验证**。未执行 GPU 测速，未读取正式 test observation，未生成 300 观测公共面板，也没有加速或成功率结论。

入口为 `scripts/profile_observation_to_action.py`，独立复算为 `scripts/analyze_observation_latency.py`。复用冻结的 `libero_runtime`、同一轻量 `OpenVLAOFTTokenPolicy` 和新的 `SelectorRolloutPolicy`；不改 G0/G1/D1。

## 计时口径

- 每次输入原始模拟器图像、位置、四元数、夹爪状态及指令；每次重做旋转、JPEG/resize/crop、proprio 归一化、H2D、视觉编码、条件编码、全部 scorer/Top-k、packing、LLM/action head、D2H、反归一化及夹爪处理，结束时已有可执行 CPU `[8,7]` action chunk。
- 主测仅在完整调用前后 CUDA 同步，用 CPU 高精度时钟计时。主调用不挂阶段计时器；不除以 8 冒充单次 observation 延迟。
- 分项另跑一轮完整流水线，五段为 `preprocess`、`vision`、`condition_selection`、`policy`（含 packing/LLM/action head）、`postprocess`。CUDA events 与 CPU wall 分别记录，不逐段同步，不要求分项相加等于总延迟。CUDA stream 间隔含提交间隙，不能称纯 kernel 时间。
- 数组文件加载、模型加载、日志、遥测和模拟器步进/渲染在主计时外。模型加载另记；完整 GPU 占用、硬杀和基础设施开销用 Slurm 账单补齐。
- 每方法/预算/checkpoint 50 次预热，公共面板 5 轮；方法及 cold/hot 次序由 seed 1017 打乱。额外 1 轮分项，所有调用均进入账本。
- **当前适配器未缓存语言。** cold/hot 两种记录均完整重算语言，`instruction_cache_enabled=false`，不能解释为语言缓存收益。工具仅为未来语言专属缓存预留 clear/prime 接口，禁止视觉、索引、教师动作和策略输出缓存。

主报 ms/chunk 的均值、median、p95、逐轮结果和同观测 dense 配对加速比。5 次重复先按观测平均，再按 episode 整簇 bootstrap；不将重复或 token 当独立样本。常驻 allocated/reserved 和各调用峰值分别保留。每个 block 只加载一个 scorer；reserved 来自同一已预热 allocator 的历史，不能将其解释为独立进程的最小显存需求。

## 输入文件约定

方法文件 schema1，例如：

```json
{"schema_version":1,"methods":[
  {"name":"dense","kind":"dense"},
  {"name":"uniform128","kind":"uniform128"},
  {"name":"cti128_seed17","kind":"selector","target_tokens":128,
   "checkpoint":"/server/checkpoints/cti_seed17/best.pt",
   "checkpoint_sha256":"<已核对的64位SHA256>",
   "training_report":"/server/CTI-VLA/results/g3_seed17.json",
   "training_report_sha256":"<已核对的64位SHA256>"}
]}
```

路径应替换为已验证服务器实际路径，不生成示例权重。选择器只接受 G3 报告所固定的 best checkpoint，检查训练身份、scale、源码/条件/数据版本；正式模式另验 train302/906、有效 validation189、14496 标签覆盖。

公共面板是由 `signed_payload(payload, PANEL_NAMESPACE)` 固定签名的 schema1 JSON。`PANEL_NAMESPACE` 来自 `evaluation.profiling`。面板目录须包含下列引用文件及 SHA256，引用不能越出目录：

| 字段 | 内容 |
|---|---|
| `source_kind` / `arrays_preprocessed` | `simulator_raw` / `false`，不接受 RLDS 变换后的输入 |
| `split` | `development` 或冻结后的 `test` |
| `model_revision` | 完整 base checkpoint revision |
| `initial_states_manifest` | 原始已签名初态 manifest 的 `{path,sha256}` 副本 |
| `episodes` | 每项含 `episode_id`（state trial ID）、`task_name`、`instruction`、`policy_calls`、`dense_receipt:{path,sha256}` |
| `observations` | 每项含唯一 `observation_id`、`episode_id`、`query_index`、`phase`、`arrays:{path,sha256}` |

每个 NPZ 只保存 `agentview_image`、`robot0_eye_in_hand_image`、`robot0_eef_pos`、`robot0_eef_quat`、`robot0_gripper_qpos` 五个原始数组。禁用 pickle。原始数组哈希必须等于 dense 实际调用日志的 `observation_sha256`，不能仅重新签名 NPZ 来替代真实来源。

每条 dense receipt 是该条真实轨迹记录，需包含 `method=dense`、`status=completed`、`state_trial_id`、`initial_state_sha256`、`instruction`、`model_revision`、`policy_calls` 和完整 `chunks[].observation_sha256`。不能用人工摘要冒充轨迹日志。`policy_calls=N>=3` 时选择 query index `0, floor((N-1)/2), N-1`，阶段依次 first/middle/last；N=2 只留 first/last，N=1 只留 first。短轨迹缺额单列。

正式 `test` 面板在打开任何初态、轨迹或 NPZ 引用前要求 `--formal --freeze-receipt` 及通过的 G0。冻结文件应为实际审核产物，包含：`stage=final_evaluation`、`status=configuration_frozen`、`model_revision`、`methods_sha256`、`initial_states_manifest_sha256`、预选 100 个 `profile_panel_state_ids`（10 tasks×10 states）；同时固定 `input_version`、`packing_version`、`action_version`、`stats_key`、`runtime_sha256`、`g0_report_sha256`、`asset_manifest_sha256`、`protocol_manifest_sha256`。面板及每条 dense receipt 记录该文件的 `configuration_freeze_sha256`。禁止为绕过护栏自行填写“已冻结”。本轮没有创建此文件。

## 后续执行

先对已获授权的 development 原始数组面板执行 `--prepare-only`：校验来源，返回调用预算，不加载模型、不查询 GPU。正式面板只有冻结后才准备。

服务器运行要求 Linux、Slurm 单可见 GPU、明确 `--uncontended-gpu` 声明、通过的 G0 报告、checkpoint/cache/output 路径；不能在登录节点启动。若从只读源码 snapshot 运行，测量及分析入口均传 `--project-root <主项目根>`，结果回写该项目的 results，不能写进源码 snapshot。命令结构：

```text
python scripts/profile_observation_to_action.py --panel <raw_panel.json> --methods <methods.json> --g0-report <accepted_G0.json> --checkpoint <server_base> --cache-directory <server_hf_cache> --output <project/results/new_run> --uncontended-gpu
```

输出 `config.json`、逐调用 durable `calls.jsonl`、`measurements.json`、`summary.json`。完整成功需要 base 与所有 selector/checkpoint 报告的结束校验通过。不得覆盖旧输出；中断的 start 保留为 unknown，失败调用保留成本。重跑使用新目录，不把不同运行的有利片段拼接。

独立分析输出必须位于原运行目录之外；读取已完成摘要固定的 measurement/journal SHA 后复算。实际正式面板捕获、GPU计时、硬件无竞争核验、每 seed 的闭环与 Pareto 联结均仍待实验执行。
