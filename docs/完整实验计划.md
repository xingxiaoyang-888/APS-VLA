# CTI-VLA 完整实验计划

版本：v1.0，2026-10-14。状态：**实验实施计划，未取得方法收益结果**。项目根目录：`F:/CTI-VLA`。

研究目标：在冻结 OpenVLA-OFT 的条件下，检验“根据当前保留集合学习真实删除影响”能否改善视觉 token 选择，并获得有证据支持的控制性能、端到端延迟及训练成本折中。

**执行主线：闭环接口验收 → 小规模机制诊断 → 有限预算标注与训练 → 匹配基线与消融 → 冻结配置 → 正式闭环和测速 → 跨 suite 验证。主预算为 128 tokens，256/64 tokens 补充压缩曲线。**

方法定义以 [研究方案](研究方案.md) 为基础；本文件细化实验执行、样本规模、统计口径和停止条件。下文数值是计划配置，不是实验结果；修改后须记录版本、理由及是否已经查看测试结果。

## 2. 待回答的问题与可证伪结论

| 编号 | 问题 | 必须提供的证据 | 不足以支持结论的情况 |
|---|---|---|---|
| H1 | 语言与 proprio 是否帮助选择？ | 保持教师条件不变，分别移除选择器条件的匹配消融；真实 packed 误差及闭环结果 | 仅展示注意力图或不合理的跨任务指令替换 |
| H2 | 当前集合的信息是否有用？ | 同 token 在不同集合的标签变化；集合标签与完整上下文标签、动态与固定集合摘要的受控对比 | 只增加数据量/参数量后性能提升 |
| H3 | 真实删除监督是否更适合部署？ | 在相同集合、候选和模型下对比删除与均值替换监督，最终统一真实 packing 评测 | 将更长训练或更多教师调用误认为干预收益 |
| H4 | 小网络能否学到有用的选择规则？ | 教师边际诊断、学习选择器、均匀/随机与 LOO 的逐级对比 | 教师有效但学生只有离线相关性改善 |
| H5 | 方法是否具有实际效率价值？ | 闭环成功率—完整 observation-to-action 延迟曲线，并报告标注及训练成本 | 只报 LLM 时间、FLOPs、token 数或单次推理 |

“集合”指当前保留 token 的集合；“LOO”指 leave-one-out，即逐个移除一个 token 测影响；“Pareto”指不存在另一方法同时具有更高成功率和更低延迟。以上均是待验证假设，不预设新方法必然优于基线。

## 4. G0：先验收完整闭环链路

按固定 commit 的 [OFT 评测入口](https://github.com/moojink/openvla-oft/blob/e4287e94541f459edc4feabc4e181f537cd569a8/experiments/robot/libero/run_libero_eval.py) 对齐 observation 构造、图像处理、proprio 与动作后处理。Spatial 的计划设置为 10 步初始等待、最多 220 个控制步、每次执行 8 个动作、每任务正式 50 次试验；使用第 3.3 节备用划分时改为 40 次。模拟器、LIBERO、MuJoCo、robosuite 及 EGL 版本在安装后固定并记录。

验收顺序：

1. 对原始模拟器两视角图像，逐项对齐 180° 旋转、官方 resize、面积比例 0.9 的中心裁剪、通道顺序、数值范围、指令模板和 processor 输出。明确 RLDS 已应用的变换，防止重复旋转或重复归一化；依据固定版[图像工具](https://github.com/moojink/openvla-oft/blob/e4287e94541f459edc4feabc4e181f537cd569a8/experiments/robot/libero/libero_utils.py)与[预处理实现](https://github.com/moojink/openvla-oft/blob/e4287e94541f459edc4feabc4e181f537cd569a8/experiments/robot/openvla_utils.py)。
2. 对齐 proprio 的位置、姿态转换、夹爪分量及 checkpoint 的 `bounds_q99` 统计/掩码；对齐动作反归一化、夹爪二值化和符号。
3. 用 90 个开发观测比较官方 dense 与迁移 dense 的中间张量、归一化动作、实际环境动作。相同输入与计算顺序优先要求逐项相等；BF16 差异的预设数值上限为归一化动作 max absolute error≤0.002，同时要求处理后的夹爪指令完全一致。出现非零误差必须定位来源并保存分布及复算结果，超过阈值先修实现，不临时放宽。
4. 在至少 3 个任务各 5 个开发状态上跑官方 dense、迁移 dense、均匀 128；dense 两条实现对比每步动作、首次分歧和终止结果。若仅有已解释的数值噪声，仍须验证配对终止结果一致；不一致则进入人工检查，不能仅凭单帧阈值通过就扩大研究评测。
5. 检查实际 sequence 长度、每相机保留数、原序索引、position IDs、attention mask 和动作切片。记录选择器/策略调用数，CTI 一次决策只允许最终一次策略调用。
6. 增加断点恢复及失败记录检查：异常不得默默跳过，重复 trial 不得重复计入成功率，录像关闭不应改变策略行为。修正 smoke 的选样和 split 检查，只能从 train manifest 取工程训练样本。

**G0 通过条件：**官方链路对齐、开发闭环可复现、初始状态隔离固定、资产与配置有哈希。未通过时只修接口，不生成正式标签，不把接口失败解释为方法失败。

完成正式预处理后更新 input/feature/label 版本并重建缓存；不能沿用当前 processor-only 的视觉特征或标签作为正式实验输入。

## 5. G1：机制诊断与教师选择能力

### 5.1 教师目标及共享约定

令 S 表示保留集合，c 表示指令与归一化 proprio。所有误差都与同一完整教师的归一化动作比较：

```text
a_full = F(all 512 visual tokens, c)
E(S) = mean(abs(a_S - a_full))              # 8×7，共 56 项
y_i(S,c) = E(S without i) - E(S)             # 允许负值
```

正标签表示删除该 token 会进一步增加偏差，因此 Top-k 保留高分 token。该量不是环境回报差，也不是因果识别意义下的效应。完整集合的删除标签理论上非负；部分集合出现负值合理。完整集合明显负值、非有限值或缓存身份冲突需立即定位。

标签必须登记当前 S、候选 i、参考动作、删除前后误差、模型与处理版本。对 10 个观测重复计算同一干预，估计数值噪声；近零标签单独分析，不把精度噪声当作符号翻转。重复性检查使用相同精度和后端，不能只为 CTI 切换更高精度。

### 5.2 90 观测诊断矩阵

| ID | 设置 | 读数与解释 |
|---|---|---|
| D1 条件变化 | 至多 10 个确实支持两条合法任务指令的观测，每条件固定 8 个 full 删除候选，并分别计算该条件的完整教师参考 | 只比较教师标签敏感性；至多 180 次前向。不存在合法配对则不强做；选择器去语言/proprio 的比较放到训练后的 A1 |
| D2 集合变化 | 每观测 S=512；S=256/128 各取随机与空间均匀两种，共 5 个集合；每集合每相机 8 个候选 | 用同一组锚点 token（每相机 8 个）构造都包含它们的集合；比较同 token 的标签、符号和排名，明确这是受约束的诊断分布 |
| D3 干预变化 | D2 的同一 S、同一候选分别做真实删除和均值替换 | 统计锚点标签差异与候选内排序一致性；16 个候选不能代表全 512 排名，最终集合质量由第 5.3 节及 A4 评测 |
| D4 阶段与维度 | 按任务、时间早中晚、末帧/非末帧分组；分位置/旋转/夹爪及 chunk 步分析动作误差 | 确认改进不只来自静止帧或单一动作维度；不改变主损失定义 |

D2 每观测最多 `1 + 16 + 4×(1+16) = 85` 个策略样本前向，90 观测最多 7,650 次。D3 可复用相同 packed 基准动作，另增加至多 90×5×16=7,200 次替换前向；实际命中缓存和批处理情况另计。D1 的条件诊断预算单独记录，不能隐含进上述数目。

### 5.3 极小子集的真实教师边际选择

固定 12 个 train 观测：4 个任务各一条轨迹的早中晚；在查看标签前按任务名称排序和固定种子抽样。其作用是排除“监督目标本身无用”，不代表全 suite 的成功率。

比较：空间均匀、随机、完整上下文 LOO 静态排名、**每阶段重新计算实际删除边际**的教师选择。可复现 ACL 后加入同一面板。每种方法均输出 256/128/64 的最终 packed 动作。

对一个观测，完整教师 1 次；在 512 上逐个删除需 512 次；256 集合基准加候选需 257 次；128 集合基准加候选需 129 次；最终 64 集合再评估 1 次。因此三阶段路径最多 **900 次样本前向/观测，12 个观测 10,800 次**。256/128 的基准动作已兼作该预算的评估；缓存共享后另记实际数量。该方法不作为低延迟部署基线。

900 次只覆盖教师路径。完整上下文 LOO 与它共享首次排序和 256 集合，另需评估其 128/64 两个集合，即新增 2 次；均匀三预算新增 3 次；随机 3 seeds×三预算新增 9 次。因此上述核心配对面板上界为 **914 次/观测，合计 10,968 次**，ACL、数值复查或额外搜索另计。

它是“与 CTI 同调度的真实教师边际选择”，**不是全局最优 oracle**。若无优势，最多在其中预登记的 3 个观测上诊断较小删除步长，每观测新增上限 5,000 次前向，记录步长与候选数。不能无限搜索后只报告最优样本。

**G1 继续条件：**不存在标签/packing 错误，且至少在主预算 128 上看到跨任务和阶段一致的 packed E 改善趋势，教师边际方法值得学习。若真实教师也不优于静态 LOO/均匀，先查批量删除步长、误差目标和任务阶段，不扩网络或正式标注；若只有 64 有效，记录主预算修改原因，冻结新假设后再继续。

## 6. G2：有限预算标签生产

### 6.1 首版采样

每个观测两个集合、每集合 8 个候选。第一个集合固定完整 512；第二个为 256 或 128，在每任务和时间阶段内交替分配，尽量等量。第二集合的随机/空间均匀来源各占约一半，均为每相机等额预算；候选每相机均匀无放回抽 4 个。记录不足整除时的确定性分配规则及实际计数。

完整集合需参考 1 次 + 8 次删除，第二集合需基准 1 次 + 8 次删除，即**首轮最多 18 次/观测、16 个标签/观测**。一般两个非完整集合才是 19 次上界。以下为无跨记录复用时的理论上界，不是已花费量：

| 用途 | 观测 | 标签 | 策略样本前向上界 | 执行时机 |
|---|---:|---:|---:|---|
| train | 906 | 14,496 | 16,308 | G1 通过后 |
| validation（排除工程曝光轨迹） | 189 | 3,024 | 3,402 | 首轮训练前固定；不得拟合尺度 |
| test | 198 | 3,168 | 3,564 | 最终冻结后；只有需要正式标签诊断时才生成 |

离线 E 的 checkpoint 验证还需每预算一次最终策略前向，其成本独立统计。不得将这些缓存动作传入部署计时。

### 6.2 一轮路径补标

初版 seed 17 模型训练完成后，冻结其路径，在 train 中预选每任务 10 条轨迹、共 300 个三阶段观测，采集该 selector 产生的 S=256、128，每集合 8 个候选。新增最多 4,800 标签；完整参考已缓存时每观测最多 18 次，共 5,400 次前向。

先在验证集比较有/无补标；确认值得采用后，对所有训练种子使用**同一份冻结补标缓存**，从头训练，清楚说明这是共享一个 pilot 路径生成器的协议。主结果报告补标成本和生成器 seed；额外的路径 seed 敏感性属扩展实验。补标只进行一轮，不能依据 test 的失败回填样本。

补标价值必须对比同样新增 4,800 标签的随机/均匀集合控制组；分别报告相同标签数与相同累计 GPU 时下的结果，防止把更多监督归因于路径覆盖。

### 6.3 缓存与标注验收

缓存键包含模型、数据、预处理、条件编码、packing、action 及标签规则版本，以及 episode/step/S/i。保存候选索引、真实保留掩码、两相机数量、原位置、signed 标签与前后误差。参考动作须与当前输入和条件一致。

标签生成必须可按记录恢复；写临时文件后原子落盘，重复运行不重复计数。随机抽查至少 1% 记录重算；训练标签只属于 train；统计每任务/阶段/集合大小/候选相机的覆盖、正负与近零比例、分布尾部。标签完整不代表实验成功。

## 7. G3：选择器训练与选模

### 7.1 首版可执行配置

| 项目 | 计划值 |
|---|---|
| 结构 | 现有 `ConditionalInfluenceEstimator`；hidden=256；视觉/相机/patch 编码；轻量带位置的指令编码；proprio MLP；分相机 mean/max 集合摘要 |
| 输出及尺度 | 单个线性 signed 输出；用 train 标签 RMS 拟合唯一正尺度，不中心化，不逐样本归一化 |
| 默认损失 | Huber，delta=1.0；ranking weight=0；梯度裁剪 1.0 |
| 优化器 | AdamW，lr=3e-4，weight decay=1e-4；首版不使用学习率调度 |
| Batch | 16 个“观测—集合”记录，每记录 8 个候选；显存不足时 microbatch+累积保持有效 batch=16 |
| 训练上限 | 30 epochs；每 epoch 遍历所有训练记录并固定 seed shuffle，不按低 loss 丢弃任务 |
| 模型选择 | 每 2 epochs 验证一次真实 packed E；连续 5 次未改善提前停止；恢复最佳 checkpoint |
| 主训练 | 同一冻结数据/超参数，用 17、23、41 各从头训练；同时保存 latest 与 best |

一份选择器支持三个 token 预算。checkpoint 主选模指标为 **validation 上 k=128 的任务宏平均 E**，每任务内部三个时间阶段等权；并列时选更早 epoch。256/64 为诊断项，不在看到 test 后改用它们挑 checkpoint。正式报告全部三个 seed，不选最好 seed。

最多 15 次选模评估，每次 189 个 k=128 策略前向，即每训练 run 最多另加 2,835 次；完整参考已缓存。256/64 的离线验证、基线及重跑如执行另计，不能藏入免费的“训练验证”。

最多在 seed 17 上比较 lr={1e-4,3e-4,1e-3} 三个配置；其余默认固定。若需要比较 hidden={128,256} 或 ranking weight={0,0.1}，一次只扩一个轴，记录总搜索次数和费用，不做组合网格。所有受控学习基线获得相同选模频率和搜索次数上限；原生基线另登记作者设置。

### 7.2 训练健康检查

训练前检查输入 detached、教师 eval、VLA 参数无梯度、优化器只包含选择器及条件模块。训练时保存 loss、raw/normalized label 分布、梯度范数、参数量、峰值显存、吞吐与累计时间；训练后确认 VLA 权重哈希不变。

验证至少包含：真实 packed E 均值/中位数/p95；同集合候选的 Spearman 与高影响 token recall；各任务和时间阶段分组结果。常数标签集合的 Spearman 记为不可定义并报告比例，不能补成 0 或 1。bootstrap 以 episode 为单位，不把同轨迹的三个观测或多个 token 当作独立样本。

checkpoint 需保存选择器权重、优化器、epoch/step、RNG、训练尺度、manifest 和配置哈希。用同一小训练集验证中断恢复与连续运行的一致性后才启动长训练。训练 checkpoint 不回传本地；本地只登记路径、SHA256 与评测配置。

**G3 继续条件：**seed 17 首轮在验证主预算上优于匹配的均匀及静态标签基线，且改善覆盖多个任务/阶段，再跑开发闭环和其余 seed。最终至少两个训练 seed 改善方向一致、尾部无明显恶化，才进入全量闭环。未达到时先检查拟合差距及标签分布，只允许在既定开发预算内调整，不打开 test 寻找原因。

若基线使用动态层内剪枝或额外前向，不能只按“最后剩余 128 token”声称计算匹配；同时给出逐层 token 数、策略调用次数和实测延迟。原生版本保留作者机制，受控版本命名为“matched”，两者不能混写。相同 token 数和相同延迟是两种不同对比，应分别作图。

### 8.2 核心消融

先在 k=128、seed 17、validation 和开发闭环筛查；最终支撑论文主张的消融须补全 3 seeds 和固定正式初始状态。负结果同样保留。

| ID | 对照 | 固定条件 / 隔离因素 |
|---|---|---|
| A1 | 完整条件 vs 去语言 vs 去 proprio vs 两者均去掉 | 只改变选择器输入，教师仍读取真实指令/proprio；消融分支用固定常量，维持模块尺寸和训练预算，语言长度/mask 也不得泄漏任务 |
| A2 | 当前 S 的摘要/比例 vs 固定完整集合摘要/比例 | 相同集合标签和候选，保留相同 scorer 模块；固定版只在候选资格上使用当前 S，隔离集合信息 |
| A3 | 完整集合标签 vs 当前集合标签 × 固定摘要 vs 动态摘要（2×2） | 相同训练观测、输入集合及候选；静态标签对相同 i 使用 full 标签，解耦监督与结构变化 |
| A4 | 完整/当前集合标签 × 均值替换/真实删除（2×2） | 使用相同 c、集合面板、候选及容量；所有最终评测都真实删除并 packing |
| A5 | 一次 512→k vs 分阶段更新 | 同一 checkpoint；额外记录 selector 时间。另比较分阶段但固定首次评分，确认收益是否来自重新评分 |
| A6 | 不补标 vs selector 路径补标 vs 等量随机/均匀补标 | 同一初始标签；新增标签数量相等，报告实际查询/GPU 时 |
| A7 | CTI 标签回归 vs ACL 式动作一致性训练 | 匹配 scorer、条件输入、观测、最终预算及评测接口；如改动作者机制，必须标 matched 而非原生 ACL |

A3/A4 可复用重叠配置，避免重复训练。A4 四格固定动态 S 摘要及相同 staged 推理，固定摘要的影响只在 A3 隔离。各 cell 的样本、集合、候选清单必须完全可追溯；不能一组只在 full 上训练，另一组在更多观测/集合上训练，再把差异全归于标签。

**替换规则：**每个观测先按原始完整视觉特征计算各相机固定均值，不随 S 或候选改变。A4 对当前 S 按同一规则物理 packing，再把候选 i 替换为其相机的固定均值，保留候选的 slot、position 和 mask；标签为替换后相对完整教师的 E 减去 E(S)，仍允许负值。A4 的完整集合版本令 S=full。这样只改变候选干预，其他保留 token 一致；它是“packed 集合内替换”机制对照，不能冒称历史全长替换。历史 DIWA 若对补集也填均值以保持 512 长度或采用另一误差目标，单独标 B4；如增加全长替换 2×2，必须另外定义其集合基准动作和成本。

每个监督 cell 只用自己的 train 标签拟合一个 RMS 尺度；若结果对尺度显著敏感，再加共用尺度的控制。A5 在目标 256 时 one-shot 与 staged 必须相同；固定首次分数的多阶段选择也应与 one-shot 相同，这是排序和 tie-breaking 的正确性检查。

教师样本前向数、标签数和 GPU 时无法始终同时相等：主表给相同训练记录/标签数，附加学习曲线给相同累计教师查询或 GPU 时截断的结果。ACL 的主干反传必须计入训练时间与峰值显存，CTI 的离线教师标注和缓存也必须计入成本。

## 9. G4：闭环成功率与统计

### 9.1 规模与执行顺序

开发 pilot 固定 3 个任务，每任务 10 个开发状态，覆盖不同初始物体位置；先 B0/B1/B3/M，确认无接口异常后再跑全部对照。pilot 用于排错和去留，不支持 1–2 个百分点的收益结论。

正式 Spatial 覆盖全部 10 个任务；首选每任务 50 个最终状态，即 500 episodes/方法/预算/训练 seed。3 seeds 的学习方法每预算 1,500 episodes，三个预算 4,500 episodes；采用 40 状态协议时分别为 400/1,200/3,600。Dense 与确定性均匀无需复制成 3 个“训练 seed”，但要验证环境确定性并保留共享配对参考；随机基线用 3 个随机 seed。

各方法复用相同任务、初始状态、模拟器 seed、动作频率、等待步数、最大步数和成功判据。dense 的参考结果可以在未改变环境和配置时共享，不能因方法失败而换更容易的初始状态。

### 9.2 统计及失败处理

- 主成功率：先算每任务成功率，再对 10 任务宏平均；同时给每个 seed、均值和 seed 间标准差。成功定义使用官方环境终止/成功信号。
- 主要比较：M 对 B3、matched ACL 在 k=128 的成功率差和延迟；相对 Dense 的性能损失单列。其余预算、消融和阶段分析注明次要/探索性。
- 置信区间：报告配对成功率差的 95% bootstrap CI，重复 10,000 次；按任务内初始状态 ID 重采样，保持方法间配对，多个训练 seed 对同状态的结果共同抽取。该主区间条件于已经训练的三个模型；另报告逐 seed 配对 CI 和包含训练重复重采样的敏感性区间。对于确实共享初始化/采样随机流的 matched 方法，可配对抽训练重复；不同结构的原生基线分别抽训练重复，再共同抽任务内状态。相同整数 seed 不自动构成有效训练配对；只有 3 次训练，其随机性估计有限。
- 固定这 10 个任务为评价对象，不将 CI 描述为对所有机器人任务的泛化保证；任务间差异单列表。只有 500 条闭环也未必能分辨 1–2 pp 差异，CI 跨 0 时报告证据不足。
- NaN、越界动作、方法 OOM、策略超时及方法自身异常算失败并标原因。超时首版定义为加载/预热后单次决策超过 60 秒的防挂死 watchdog；这不是机器人实时控制截止时间，deadline miss 若研究需另设实验。机器抢占、渲染服务故障等基础设施失败保留日志，修复后重跑完全相同 trial ID，所有方法用同一规则。不得只重跑失败轨迹取最好一次。
- 若 test 暴露实现 bug，修复后给新协议/代码版本，对受影响方法全部重跑，保留旧输出；已查看过的数据不能重新称为首次盲测。

首版可将“相对 Dense 不劣于 2 pp”登记为实用目标：只有差值 CI 下界高于 −2 pp 才支持该口径，未达到统计精度时只报告估计和区间。该阈值是预设研究目标，不是已有性能承诺。若正式使用多个显著性检验，另报告 Holm 校正结果，不从多预算/多消融中挑最显著的单个结果。

### 9.3 失败分析

固定分类规则：定位/接近失败、接触或抓取失败、持物丢失、放置失败、任务超时、接口异常、不明确。对成功变失败及失败变成功的配对轨迹都分析；每类报告数量和分母。视频样本按 trial ID 抽取，不能只展示新方法成功的案例。失败分类人员尽量不看方法名，无法盲判时说明。

## 10. G5：端到端延迟、显存和总成本

### 10.1 延迟边界

主延迟定义为：**原始 observation 数组与指令就绪 → 可交给环境执行的完整 action chunk 就绪**。包括图像/proprio 处理、CPU→GPU、视觉编码、指令条件编码、所有阶段 scorer、Top-k、packing、LLM、action head、GPU→CPU、动作反归一化和夹爪后处理。

主计时不包含模拟器物理步进、图像渲染、录像编码和磁盘日志；另报告完整 rollout 墙钟时间。不要把 LLM 时间称为端到端延迟，不将 chunk 延迟除以 8 后仍称 observation-to-action 延迟。若给每动作摊销时间，单独注明其含义。

允许缓存同一任务的指令编码，但两种情况分开测：任务首轮的冷指令、连续控制的热指令。不得预先缓存视觉特征、选中索引、教师动作或策略输出进入主测速；各方法相同地处理公共可缓存项。

### 10.2 测量协议

| 项目 | 固定协议 |
|---|---|
| 负载 | batch=1、单条同步控制流、单卡，无其他 GPU 工作负载；关闭录像和逐帧控制台输出 |
| 公共输入 | 从正式 dense 参考轨迹中，预选每任务 10 个初态，保存每条轨迹首/中/末三个策略查询处的原始模拟器 observation，共目标 300 个；不足三个查询则全部保留并报告实际数 |
| 预热与重复 | 每方法/预算/正式 checkpoint 50 次模型预热；公共面板完整运行 5 轮；方法顺序用固定种子打乱；冷指令测量只清指令缓存，不撤销 kernel 预热 |
| 同步 | CUDA 同步→启动 CPU 高精度时钟→完整流水线→CUDA 同步→结束时钟；分项另用 CUDA events/CPU 计时，避免逐段同步扰乱主测 |
| 报告 | ms/chunk 的 median、p95、均值；相对同批 dense 的加速；逐轮统计及观测配对区间 |
| 环境 | GPU/驱动/CUDA/torch/attention 后端、CPU、精度、功耗/温度及可获得的频率、资源配额、Slurm JobID |
| 显存 | 模型常驻、推理峰值 allocated/reserved 分开；训练 scorer、标注、ACL 等分别记录峰值 |

公共输入面板在正式配置冻结后生成，以相同原始图像/proprio 测全部方法；数组加载/文件解码在计时外，旋转、resize、crop 等策略预处理必须在计时内。每个训练 seed 的最终 checkpoint 均测速，Pareto 图使用与成功率相同的模型集合并保留逐 seed 数据。另报各方法实际闭环访问状态上的延迟，避免把 dense 状态分布当作所有策略的访问分布。

编译或 kernel 自动调优如启用，对所有兼容方法统一开关并单列编译/首次运行成本。分项时间不强求相加等于总时间，异步与 profiler 开销须解释。N 个观测重复 5 次不是 5N 个独立环境状态，CI 按 episode/观测分组，不能按重复次数虚增样本量。

Dense 也使用只返回所需动作的同等轻量推理入口，不额外保存全部层 hidden states；官方慢调试路径只作正确性参考，不能用它放大加速。若补充 198 个 RLDS test 观测测速，必须单列已应用变换和计时边界，命名为离线输入诊断，不与模拟器原始 observation 的主测速混合。

### 10.3 成本账本

每个实验记录：参考/基准/干预样本前向数、实际 API 批次数、各序列长度、缓存命中数、GPU 数×占用小时、墙钟时间、CPU 小时、读写字节、峰值显存。批量 8 个干预的一次模型调用仍是 8 个样本前向。

```text
总方法开发成本 = 特征与参考缓存 + 标签生成 + 补标 + 超参数搜索 + 正式训练
完整研究成本   = 总方法开发成本 + 基线复现 + 所有评测 + 失败/重跑成本
复用部署成本   = 固定模型的推理时间；与首次标注/训练成本分开
```

先用 90 观测实际测不同长度前向速度，再估计剩余 GPU 小时：`Σ(各长度实际样本数 × 同长度实测秒/样本)/3600`，批处理、缓存及 I/O 单独修正。不能用一次冒烟时间线性推断所有成本，也不预写加速倍数或服务器费用。

可附同设备的摊销分析：新增标注/训练 GPU 秒除以每次决策节省秒数，得到大致需要的决策次数；若分母≤0 则无时间回本。异构硬件/并行占用不可直接相除，需统一口径或放弃该数值。

## 12. 扩展、风险和停止条件

跨 suite 首选 LIBERO Goal，再考虑 Long。区分两种问题：

1. **同方法重训：**使用对应 suite 的冻结 OFT 基座，重新分 episode、标注和训练选择器；检验方法可重复性，不称零样本迁移。
2. **选择器迁移：**Spatial 选择器不更新权重、不重新拟合尺度；固定目标 suite 基座和输入兼容规则，与目标 suite 自训练选择器、dense、均匀对照。不同基座特征分布可能变化，负结果同样报告。

Long 的动作时域、任务时限与数据定义需按固定官方版本重新验收，不直接复制 Spatial 的 220 步或数据归一化统计。额外模型和数据先登记来源/容量，权重仍只在服务器保存。

| 观察到的情况 | 后续动作 |
|---|---|
| Dense 无法稳定对齐官方 | 暂停研究结果采集，修图像/proprio/action/packing/环境 |
| 真实教师边际在相同调度下无优势 | 有界诊断删除步长/误差目标；不扩大 scorer 或数据 |
| 教师有效、学生无效 | 检查标签噪声、分布覆盖、拟合能力；优先统一尺度和候选覆盖 |
| 离线 E 改善而闭环变差 | 检查夹爪/近接触阶段、误差尾部和 rollout 分布偏移；修改目标须新版本重新验证 |
| 控制尚可但 selector 开销抵消收益 | 优化可复用条件/投影计算后统一重测；保留真实总延迟，不隐去 scorer |
| CTI 与 ACL 效果接近但总成本更高 | 缩减或改变贡献主张，不以“无主干反传”直接推断更便宜 |
| CI 太宽或收益只在单 seed/单任务 | 报告不确定性；增加预登记重复或收缩结论，不能挑最好子集 |
| 截稿前无法完成正式强基线/闭环 | 缩减扩展，不削弱公平性；保留未完成项，不能把计划写成结果 |

不在首版同时加入世界模型、critic、在线 RL、大主干微调或自由动态 token 预算。只有当前假设被明确证伪或完成后，再提出独立方法版本。
