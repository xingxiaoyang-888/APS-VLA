# G1 D4 离线分析

实现：[`scripts/analyze_g1_d4.py`](../scripts/analyze_g1_d4.py)。这是 CPU 分析工具，当前仅用合成日志验证；尚未分析正式 G1 结果，不构成继续训练的科学许可。

正式 G1 全部完成并回存后运行：

```powershell
python scripts/analyze_g1_d4.py --run-directory results/g1/正式运行目录 --output-directory results/g1_analysis/正式运行目录
```

工具要求完整冻结 90/12 面板、真实 train 身份、最终 checkpoint 校验记录，以及与 `finalization.json` 一致的全部 observation/journal 文件 hash。它从原始动作查询重放 D2/D3、教师路径和随机/均匀/static 对照；重算值若与原摘要不同则报错。分析与采样核心必须和生产日志的源码 hash 一致，不能把新版算法静默用于旧日志。

输出 `summary.json`、观测级指标、候选 signed 标签及分组 CSV，另导出三张 PNG/PDF 科学图。按任务、早/中/晚和末帧分组；包括符号翻转、未定义排名比例、动作 7 维和 chunk 8 步误差，以及每个预算的 `teacher − baseline` 配对差，负值表示教师路径误差更小。

默认以 episode 为单位 bootstrap 10,000 次，seed=917；候选 token 和随机基线 3 个 seed 先归并至同一观测，不增加独立样本数。常数标签的 Spearman 保持 null；仅一个有效 episode 时不输出置信区间。区间为逐项探索性区间，未做多重比较校正。teacher 只有 4 个 episode，每个选定任务仅 1 个，区间只能探索性解读。当前 late 与 final-frame 完全重合，无法分离两类效应；末帧也不代表静止。

`summary.json` 永远写 `go_no_go=not_decided_requires_scientific_review`。查询日志成本只覆盖相应教师前向，完整成本还需结合 observation attempts 与调度器记录。该工具不运行策略、生成权重、接触 test 数据或修改 G1 原始产物。
