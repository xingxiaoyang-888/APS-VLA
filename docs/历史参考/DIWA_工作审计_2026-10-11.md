**一、现在实际在做什么**

当前主线可以准确写成：

双视角图像 → 冻结视觉编码器与 projector → 512 个视觉 token → 轻量 DIE 打分 → 保留部分 token 并缩短前缀 → 冻结 OpenVLA-OFT 语言主干与 L1 action head → 8 步、每步 7 维的动作 chunk。

教师标签的实际生成方式是：在完整 token 上替换一个 token，比较替换前后模型输出动作的 Huber 差异。之后用这些标签训练 DIE。这里的世界模型、未来状态预测、价值估计和潜在空间重组尚未实现。

**二、实验进度与结果应如何解释**

固定 120 样本版本的设置为：OpenVLA-OFT LIBERO Spatial checkpoint，revision 为 6d0231af0e48c5985f1ff86908f4674b84bc049b；双图与 proprio，确定性 L1 action head，动作形状 8×7。DIE 的 token 维度 4096、hidden 256、metadata 32；raw、quantile、hybrid α=0.75 各训练 seed 17、23、41，30 epochs。

这里的 120 是观测数：

- 训练：96 个观测，22 个 episode，7 种语言指令。
- 验证：24 个观测，5 个 episode，4 种语言指令。
- Episode 没有交叉；所有样本来自同一个 shard。
- 采样时间仅为 step 0、8、16、24、32；相对于 84–148 步的完整轨迹，明显偏前段。不能据此判断接触、放置、后期纠错和长时任务的选择质量。
- 120×512 个 token 标签不等于 61,440 个独立场景。经过多轮选型的这 24 个验证观测，也不宜继续当最终测试集。

Ensemble 的 m=8 candidate top-1 coverage 达到 23/24，即 95.83%；candidate relative oracle regret 为 0.02689。这说明八个候选中通常能包含教师认为最重要的那个 token。它没有测量“保留这八个 token 后机器人是否成功”，也没有测量“删除其余 token 后动作改变多少”。

候选 regret 的实际定义是：

\[
R_{\mathrm{candidate}}=
\frac{\max(0,\max_i \Delta_i-\max_{i\in \mathrm{TopM}(\hat\Delta)}\Delta_i)}
{\max(\max_i\Delta_i,10^{-12})}.
\]

第二项还使用了教师真值，在模型提出的候选中取最好者。因此 m 表示教师候选预算；最终部署的保留数 k 是另一个量。Full relative oracle regret 也只是预测首选 token 与教师最优 token 的影响值差距。二者均不是环境回报损失。[指标实现](F:/DIWA/scripts/evaluate_stage_a_gate.py:99)

**三、方法和代码中最需要先解决的问题**

**1. DIE 缺少定义目标所需的任务信息。**

实际 query 是视觉 token 的均值；在当前全零 intervention mask 下，context 也取视觉均值，removed ratio 恒为 0。DIE 不读取 proprio。use_film=False 的视觉编码器也未把语言预先混入这些 token。

所以，同一画面分别要求“拿红杯子”和“拿蓝杯子”时，教师的动作与 token 影响可能不同，而当前 DIE 的输入完全相同。这个歧义不能靠增加 MLP 容量或更多同类标签消除。应把可在大模型前取得的语言表征和归一化 proprio 明确接入，并通过同图不同指令的对照检验价值。加入这些条件是使方法定义成立的修正，本身不足以构成论文贡献。

证据：[query 构造](F:/DIWA/diwa/evaluation/teacher_pilot_openvla_oft.py:65)、[DIE 输入](F:/DIWA/diwa/models/influence/die.py:77)、[上游视觉编码](F:/DIWA/models/openvla-7b-oft-finetuned-libero-spatial-6d0231a/modeling_prismatic.py:438)。

**2. 条件影响目前停留在 API，实际训练还是完整上下文 LOO。**

Teacher 和 DIE 接口支持非空干预集合，但生成标签、训练及 selector 都传全零 mask。当前数据没有教会模型“其他 token 已经被删掉之后，这个 token 还值多少”。这恰好是原方案最想强调、且仍可能具有研究价值的部分。

后续缓存必须保存具体保留/删除集合或可恢复的编码，纳入缓存身份；只保存 base_intervened_count 无法区分两个等大的不同集合。相关 cache 的计数限制还会妨碍高删除比例的条件样本，需一并修正。

证据：[教师调用](F:/DIWA/diwa/evaluation/teacher_pilot_openvla_oft.py:255)、[训练 mask](F:/DIWA/scripts/train_stage_a_full_audit.py:215)、[selector mask](F:/DIWA/diwa/models/stage_b_selector.py:105)、[cache schema](F:/DIWA/diwa/data/teacher_cache.py:64)。

**3. 单 token 替换与大量 token 删除是两个不同的干预。**

教师把一个 token 换成相机组内均值，保持序列长度；推理删除多个 token，改变注意力归一化和位置关系。某个 token 单独可替代，可能只是因为另一个 token 含相同信息；把两者一起删掉会丢失信息。因此 LOO 排名正确，仍可能选出糟糕的保留集合。

最优先的诊断是：对同一保留集合分别执行 matched replacement 与真正 packing，测动作差异，并检查 LOO 高分选择能否优于均匀/随机选择。这比继续提高 candidate coverage 更直接。

**4. 部署 selector 与 profiler 的 token 顺序不一致。**

StageBTokenPolicy 将 torch.topk 的分数排序直接用于 gather；profiler 则把选中索引重新按原顺序排列。adapter 传 position_ids=None，默认使用压缩后的位置编号，未根据原始索引重建 RoPE。

必须让 teacher、训练、离线评测、闭环部署与 profiler 使用同一条 packing 路径。先保留原始序列顺序，并显式选择“保留原位置”还是“紧凑重编号”；两种位置方案的差异可做小消融。当前 full-retention 等价性检查无法发现这个只在稀疏选择时出现的问题。

证据：[selector top-k](F:/DIWA/diwa/models/stage_b_selector.py:108)、[gather](F:/DIWA/diwa/models/stage_b_selector.py:124)、[profiler 排序](F:/DIWA/scripts/profile_openvla_packed.py:85)、[position_ids](F:/DIWA/diwa/models/oft_adapter.py:137)。

**5. 术语与理论需要修正。**

- 当前标签是 action discrepancy/sensitivity，无 Q 值、回报或成功率监督。Action-Regret 容易被理解成控制性能后悔值，建议改为“动作偏差”或明确限定的代理损失。
- 设计中 I_S 表示替换集合 S，却把后续 A 称为保留集合，符号语义相反。用 S 固定表示保留集合，R 表示删除集合。
- 设计的 telescoping bound 使用 Huber 距离，但 Huber 不满足三角不等式。例如 δ=1 时，H(1)=0.5，而 H(0.5)+H(0.5)=0.25，原不等式不能直接成立。若需要路径上界，可改用 L1 等真正的度量，并明确估计误差在整条删除路径上的适用条件。
- 静态 top-k 排名不等于会逐次更新条件边际的 greedy；设计里的次模 bound 缺少可核验的正式前提。少量 synergy 诊断不能证明全局次模。
- 原 synergy 公式也不是标准集合二阶差分，应重新从一个明确定义的集合目标推导。
- 冻结表征后进行选择，并没有训练“视觉不同但决策等价状态在潜在空间聚合”。这类表征几何结论应删除，除非另外实现和测量。

证据：[集合定义](F:/DIWA/DIWA_ICLR_design_zh.md:144)、[synergy](F:/DIWA/DIWA_ICLR_design_zh.md:164)、[理论段落](F:/DIWA/DIWA_ICLR_design_zh.md:584)。

**6. 排序目标不能直接当校准风险。**

Hybrid 逐样本 max-normalize 后混合秩，ensemble 再做 z-score，保留了排序用途，但失去了跨样本绝对影响尺度。若将来要根据阈值选择预算，需要单独训练/校准风险量。

此外，所谓 mid-rank 实现实际给 ties 分配不同的 ordinal rank，相关 Spearman 实现也需规范处理 ties/常量输入。这是应修复的统计问题，尚不能据此推断所有现有数值失效；需要原缓存恢复后重新算差异。[目标变换](F:/DIWA/diwa/losses/influence_targets.py:18)

**四、截至 2026 年 10 月的新颖性评估**

旧 related work 文档截止 8 月 13 日，之后出现两篇尤其接近的工作。

| 文献 | 与 CTI 的重合 | 尚可能保留的差别 |
|---|---|---|
| [VLA-ACL，10 月 6 日首发](https://arxiv.org/abs/2610.08133) | 冻结 VLA，以全量动作与演示动作监督轻量 scorer，前置选 token、推理真实删除 | CTI 可以研究显式实际删除标签、集合条件影响及不反传大主干的训练方式 |
| [Action-JND，8 月 21 日首发](https://arxiv.org/abs/2608.21247) | 用动作对特征变化的容忍度训练估计器，指导剪枝和 KV reuse | 扰动容忍度与特定保留集合中的实际删除边际并不相同 |
| [VLA-Pruner](https://arxiv.org/abs/2511.16449) | 结合语义与动作相关性，强调语义重要性与动作重要性的差别 | 显式干预监督仍与注意力代理不同 |
| [SpecPrune-VLA，ICML 2026](https://proceedings.mlr.press/v306/wang26jj.html) | 利用动作和时序信息进行高效 token 选择 | 可作为有竞争力的免训练对照 |
| [FastSHAP，ICLR 2022](https://arxiv.org/abs/2107.07436) | 用轻量网络摊销昂贵的模型归因计算 | 不是 VLA 剪枝，但说明“离线归因、在线预测归因”不是新范式 |

VLA-ACL 应成为最优先的直接基线：[官方代码与权重](https://github.com/du-owen/VLA-ACL)已公开。其训练只更新 scorer，但梯度穿过冻结 VLA；CTI 的 forward-only 标签缓存可能降低显存压力。不过教师多次前向也有成本，需比较“标注＋缓存＋scorer 训练”的总 GPU 时。[ACL 方法和实验](https://arxiv.org/html/2610.08133v2)

已有研究也展示了特定 token skipping 设置下，门控信号看似正常却出现闭环失效。这支持把真实 rollout 纳入早期验证，不能推广为所有动作偏差指标都无用。[The Gate, Not the Cache](https://arxiv.org/abs/2608.00391)

**客观判断：**

- 工程可行：已有真实 7B 接入和 packing，第一阶段不需要训练世界模型，也不必以真实机械臂为前提。
- 原始新颖性不足：冻结教师、动作一致性、小 scorer、前置剪枝这些卖点已有直接竞争者。
- 当前方法有效性未定：DIE 的代理指标有信号，但集合删除和闭环结果仍缺失。
- 剩余研究潜力：证明高压缩下存在有实际后果的 token 冗余/协同，并用与部署一致的条件删除监督，在效果或训练资源上稳定超过直接动作蒸馏。
- 不应预设一定能形成顶会论文。若条件方法不能在控制性能、成本或解释力上带来实质增量，应停止扩展该方法，而不是加入更多术语。

**五、建议收敛成的研究问题**

建议只保留这一条主线：

> 在冻结的 VLA 中，当大量视觉 token 同时被移除时，学习实际保留集合下的动作影响，能否比完整上下文的单 token 归因及直接动作一致性蒸馏，更有效地选择 token？

这是一条待验证的假设。当前仓库还没有足够证据支持它成立，也不能据本次检索宣称“首次”。

先固定任务条件 c=(语言指令，本体状态)，N 为完整视觉 token 集合，S 为保留集合，且 Pack 包括明确的位置规则：

\[
a_{\mathrm{full}}=F(Z,c),\qquad
a_S=F(\mathrm{Pack}(Z_S),c),\qquad
E(S)=\frac{\|a_S-a_{\mathrm{full}}\|_1}{K d_a}.
\]

第一篇论文真正要优化的是固定预算下的 E(S)，并最终验证闭环成功率与完整推理时间。

两种容易混淆的条件量应分开：

\[
C_i(S)=\frac{\|a_{S\setminus\{i\}}-a_S\|_1}{K d_a},
\qquad
M_i(S)=E(S\setminus\{i\})-E(S).
\]

C_i 是当前集合下删一个 token 的动作敏感度，非负；M_i 是相对于完整教师的误差增量，可能为负。两者不相等。如果选择 M_i 为训练目标，现有强制非负的 softplus 输出和标签契约需调整。可以先研究 C_i，但不能把它直接称为优化 E 的真实边际收益。

推理时不能运行完整教师来为全部候选打分，否则会抵消加速。需要把有限状态上的昂贵干预摊销到轻量 scorer，并计入多轮选择的实际开销。第一版固定 token 预算即可，暂缓动态风险预算、世界模型、价值头与长期鲁棒性保证。

**六、接下来如何推进**

以下是建议的工作顺序；时间是用于控制投入的工作窗口，不是保证完成的 GPU 工时。当前稳定可用硬件与服务器存活状态尚未确认。

| 阶段 | 具体动作 | 产出与继续条件 |
|---|---|---|
| 0 恢复证据与修正评估，约 1–2 个工作日 | 找回 DIE 与 teacher cache；冻结数据划分和代码版本；统一 packing 顺序/位置；修 ties；补任务条件接口；跑 dense LIBERO smoke | 能重现已有离线结果；稀疏、测速与部署共用接口 |
| 1 做判别实验，约 2–3 个工作日 | 在覆盖轨迹早中晚的 50–100 个状态上，对照实际删除、替换、LOO 和少量集合条件干预 | 明确是否存在“LOO 很准但批量删除失效”，以及条件信息是否能修复 |
| 2 检验选择收益上限 | 在小子集做昂贵 teacher-assisted 集合搜索，对照 random、每相机均匀、现有 DIE、ACL | 搜索出的集合实质优于便宜方法，才值得蒸馏；它是近似搜索基准，不称全局最优 oracle |
| 3 条件 scorer 的小规模训练 | 只对多样化状态/子集标注有限候选，缓存 teacher；先一个小模型，比较 LOO 与 conditional 标签 | 独立 episode 上的 packed 动作误差曲线改善；统计标注＋训练总成本 |
| 4 提前做小闭环 pilot | 固定 2–3 个任务，每任务 10–20 个相同初始状态；dense、均匀、ACL、CTI | 用于发现灾难性退化和修实现；小样本不能支持“成功率下降小于 2pp” |
| 5 形成正式证据 | 先一个完整 suite，再增加性质不同的 suite；固定预算、硬件、action chunk、预处理与评测种子 | 成功率与端到端延迟 Pareto、重复实验/置信区间、失败类型和训练账本完整 |

阶段 1 最关键的对照是：对同一个 S 分别做“全长替换”和“物理删除”；对不同的 S 测同一个 token 的影响；对同一图像改变任务指令。三个实验分别检查干预错配、集合交互和条件输入不足。

在阶段 1 同时安排极小的 dense＋均匀删除＋现有 DIE 闭环冒烟，尽早排除部署错误和明显失败；不必等新的 conditional scorer 训练完成。阶段 4 再进行固定初始状态的四方法 pilot。

便宜的优先筛查可以直接使用现有全 token LOO 标签：取教师 LOO top-k，再真正 packed forward。若连这个昂贵标签排序也不能改善最终动作，继续把 DIE 的 Spearman 从 0.49 调高，并不一定有控制收益；需要改目标或检查位置/冗余问题。

预算 k 先固定 256、128、64 个视觉 token（两视角总计），同时记录每个相机的保留量。第一次用单 DIE，ensemble 保留作诊断或后续蒸馏教师。全 512-token 审计只在很小的诊断集上用，避免对大数据集逐 token 穷举。

训练新标签前先测每种保留长度的单次 teacher 前向时间 t_f。若每状态需要 m 次额外干预，粗略标注成本为 n×(m+1)×t_f，另加视觉编码、I/O 和调度。120 个状态完整 LOO 的调用量约为 120×513=61,560 次主干前向，标签生成并不免费。后续应比较实测总 GPU 时和峰值显存，而非只比较 DIE 的训练时间。

正式测速至少分开报告：图像处理/传输、视觉编码、DIE、选择与 packing、语言主干/action head、完整 observation-to-action latency 的中位数与 p95。保持执行的 action chunk 数、重规划频率一致。每次推理输出 8 个动作，不等于闭环观察频率提高了 8 倍。

如果需要一个便于选型的内部目标，可以预先设“整条推理链至少快约 1.2×，且成功率损失在事先约定范围内”；这只是资源分配阈值，不是论文结论。正式的 1–2 个百分点差异需要足够重复、配对初始状态和统计不确定性。

**应停止或转向的情形：**

- 在统一位置规则后，条件集合搜索对 ACL/简单选择没有实质收益：减少对该主张的投入。
- 搜索有收益、scorer 学不到：先检查输入条件、数据阶段覆盖和标签信息，再考虑网络容量。
- 离线动作误差更好、闭环无收益：研究累积误差与关键阶段，而不是继续宣称决策等价。
- 推理快了，但标注与训练成本明显劣于 ACL 且效果接近：不能以“低算力”作为主要贡献。
- 只有单一小验证集上的细微变化：不足以支持方法有效或泛化更强。

第一篇的最低合理范围是冻结 OFT 的 token 选择、实际 packing、闭环任务和完整推理延迟。LIBERO 仿真可以承担这一阶段；RoboTwin 需要匹配其动作维度和归一化的独立基座，不能把现有 7D 头直接接到 14D 双臂任务。
