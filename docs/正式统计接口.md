# 正式统计入口

`scripts/analyze_formal.py` 是纯CPU、只读分析工具。它不载权重、不调用模拟器、不读取封存初态数值。缺少全局冻结、root release或任何必要结果时返回 `pending` 与明确缺项，不输出主表。正式统计只接受完整35200个最终结果，开发结果不混入。

```text
python scripts/analyze_formal.py \
  --registration configs/experiments/formal_main_v2.json \
  --evidence results/formal_main_v2/analysis_evidence.json \
  --project-root /PROJECT \
  --output results/formal_main_v2/analysis/NEW_RESULT.json
```

输出文件须不存在；保留先前分析。所有引用均为项目内非权重JSON/JSONL的 `{ "path": "项目相对路径", "sha256": "文件SHA256" }`。登记本身的 `registration_sha256` 是已有 `json_signature(registration)`，与文件字节SHA区分。

`suites`须包括Long/Spatial/Object/Goal全4套件，`training`须包括全72个已选中训练实例。`runs`可分批提供，但同一最终状态×实例只能出现一个终结结果。程序先校验88实例全局冻结和release，再读取最终结果；`final_registry`只含索引与哈希，不允许`sealed_final.json`。逐调用检查实际预算、packing版本、单次视觉/VLA、无未来头、checkpoint、均匀网格、动作队列及配对首观测哈希。基础设施失败只计成本；`policy_error`沿既有执行器规则计失败并单独报告。JSONL尾部不完整只报pending，绝不修复或截断原始文件。

选中validation必须对应receipt中最优update与artifact SHA；重算10任务等权teacher/demo动作误差和同预算、同seed的A/B集合重合率/Jaccard，并检查A/B初始化与数据顺序相同。完整与组件测速从原始journal重算，逐实例与全局冻结身份相同，禁止用组件插桩总时间替代主延迟。

统计张量为 `4套件×10任务×40唯一初态×22实例`。每suite/task用 `default_rng(20261016)` 生成10000×40个有放回索引，全部22结果随初态簇一起抽取；所有比较共用同一组draws并保存其SHA。每轮先任务等权、再套件等权，学习方法在同轮对3个seed等权。训练seed不重抽，不当作额外环境初态。另报逐seed、逐任务/套件成功率、配对差值及三seed样本标准差。输出记录分析脚本SHA和Python/NumPy版本；登记统计参数不同则拒绝执行。

主比较为B128−A128；完整保留全部suite/预算B−A、各方法−dense及B64−A128。使用95%百分位区间，quantile算法固定linear，端点保存12位小数以消除加和舍入误差（精度远高于本轮二元计数）；相对dense的区间下界严格大于−0.02才支持2个百分点实用目标。未达门槛不代表等价。默认只报效应和区间、不生成p值；后续若展示跨套件/预算显著性，须事前另定检验与Holm校正范围。B64−A128须结合成功率区间和完整median/p95阅读，脚本不自动宣布优胜。

`final_cost_inventory.json`由root整理：`schema=formal_main_v2`、`kind=final_cost_inventory`、`issued_by=root`、`complete=true`、`registration_sha256`、`job_ids`。`accounting.jobs`须精确覆盖该列表，并包含所有证据中的job；每行至少为 `job_id/experiment/status/elapsed_seconds/gpus/mode`。作业ID去重，失败重跑、共享生成、加载、采集、两pass等实际分配GPU秒只加一次。内部phase计时不可再叠加到账单；独立运行的共享cache归属成本不是该实际总账，缺少测量时不得当零或伪造。

`cache_replay`只接受 SHA 绑定的原始 `kind=cache_replay_evidence` 清单，契约见[只读重放入口](正式缓存重放实现.md)。不能提交 `standalone_cache_cost` 手工摘要或预计算的completed结果。分析器使用同一个登记对象调用未修改的重放工具，从原始日志重新计算；重放源码SHA与全部已读取证据SHA一并写入分析输出。提供的72组报告/部署收据、四套件windows、实际账单和root完整成本清单必须与已通过核心验收的引用相同；接入绑定的core/cache引用都必须使用项目相对路径，不自动接受绝对路径。缓存清单缺项仍由重放器报告pending，不通过另一份账单或另选checkpoint补齐。

没有`cache_replay`时保留旧版`pending_real_training_logs`；有清单但自然日志或root关闭证据不足时为`pending_evidence`。核心结果齐备仍可输出`completed_core_analysis`，不把缓存pending伪装成0或阻断真实核心结果的呈现。完整自然日志核验后可输出`completed_estimate_with_limitations`，名称固定为**独立磁盘缓存操作成本估计**：每arm冷128GiB盘、2条RAM、十个500步进程边界；只用同namespace/key/操作/完整硬件身份的实际观测校准。大小缺失、未观测操作、硬件证据不足及事务未知保留unknown；覆盖部分的秒值只称subtotal，完整秒数不齐为null。经验min/max保留全部尖峰，不是CI或未知操作的界限。实际共享增量/内部phase不重复加到账单，也不当成完整独立运行成本。

完成字段分开记录：`core_results_complete`表示核心统计、完整O2A和实际总账齐备；`cache_evidence_complete`只表示独立缓存证据已关闭；`independent_cache_operations_fully_identified`仅表示该磁盘操作定义内计数和全部同身份计时校准齐备且无事务未知，仍是反事实估计。`delivery_status`为`pending_core_evidence`、`core_complete_cache_pending`或`core_complete_cache_estimate_with_limitations`。**`main_experiment_delivery_complete`始终为false**：操作成本重放不证明完整独立训练GPU账单，其他论文交付与最终完成由root核验。存在unknown不允许手填数值，也不为计费新增GPU实验。

新增接入测试用合成证据穿过原始72身份/receipt/pull/root清单→真实重放→分析→渲染链；已单测的闭环/统计/计时层及重复journal展开使用分层fixture，重复的相同合成40000流仅缓存真实函数返回值。它检验接口，不代表72组自然训练已经完成。

回存入口为 `python scripts/pull_formal_results.py --job-id 已登记作业ID`（可重复该参数）。它只查询本项目监督清单中的正式作业，不提交或取消作业，不改监督状态；运行中的共享输出目录不回存。终态输出先下载到隔离目录，前后文件清单、SHA、终态Slurm账单和登记身份均一致后发布，已有不同版本先归档；失败与部分传输仍留收据，不标为科学完成。

拉取只允许非权重结果类型，拒绝权重/封存目录、路径越界和Windows文件名冲突。闭环结果的 `panel.json` 可能含最终初态数值，因此先只读相邻 `config.json` 的执行身份：最终或未知面板在打开或哈希读取前排除；开发评测和开发测速面板必须绑定该配置SHA才可回存。最终统计只需索引/hash登记与原始trial日志，不需要最终状态数值。

正式产物与划分清单按原始字节归档，相关目录在 `.gitattributes` 中关闭换行转换，避免Windows/Linux检出改变已登记SHA。不能通过格式化或截尾重写日志来满足校验；历史版本保留。

当前仅合成数据测试；此工具的存在不代表正式训练、最终评测或正式测速已完成。
