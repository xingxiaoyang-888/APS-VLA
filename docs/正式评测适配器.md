# 正式评测入口适配

本适配器仅解决已冻结正式入口的两个工程限制：已有闭环目录不能续跑，以及官方外部源码以归档形式部署时 Git-only 校验失败。它不改变方法、策略、环境、trial 顺序、部署或计时边界，也不授权新的评测作业。

新增入口为 `scripts/ops/formal_evaluation_adapter.py`，模式为 `evaluate / collect / full / components`。沿用原入口参数，另外显式传入 `--source-root`、`--source-inventory`、`--adapter-sha256`；已有闭环目录还必须传 `--resume`。root 在运行前登记适配器文件 SHA 和作业入口。运行目录必须是项目内 `results/formal_main_v2` 子目录，源码必须是固定 `formal_main_v2_run_564be0995e` 快照，并逐个验证原 173 文件。适配器不要求 Git HEAD 与快照提交一致。

- 闭环调用冻结 `eval_formal_selector_libero.execute`。开发面板只能是登记的 `development.json`；最终面板继续经过原完整矩阵及 root release 校验，校验前不读取最终初态。
- 唯一行为绑定是私有 eval 模块的 `verify_checkout`，调用冻结 `eval_libero.verify_source_checkout`，核对固定 revision 和归档文件 SHA。profile 的 scoped loader 仅拦截该固定快照中的 `eval_formal_selector_libero`；其他加载原样执行。两项绑定均在 `finally` 恢复，原策略与 trial loop 不替换。
- 续跑先获得适配器锁和原 `.evaluation.lock`，核对 manifest、config、panel、run signature 与原始日志。缺 ledger、损坏 JSON、任何缺末尾 LF 的非空日志都拒绝；不截断，也不自动补换行。冻结 TrialLedger 原本支持部分尾部修复，本入口有意要求 root 单独审计这些情况。
- 已终态的成功、失败及 policy error trial 不重跑；完整的 infrastructure error 和未完成 start 保留并由原循环恢复。所有原日志必须保持相同字节前缀，未知尝试成本仍记未知。既有报告不能宣称超过日志中已有的终态数量。
- `collect / full / components` 仍要求新目录，不支持途中续跑。先前失败产物和 Slurm 成本全部保留，后续作业由 root 另行登记。

每次实际调用另外写入 `results/formal_main_v2/adapter_invocations/`：适配器 SHA、固定源码清单 SHA、精确文件与函数、原函数及绑定函数 code SHA、源码归档校验结果、锁内续跑证据、前后日志身份与原始字节前缀、作业 ID。收据中的 `returned` 只说明原函数返回；是否完成仍依据原始闭环/测速报告和 root 审计。参数或 release 在执行前被拒绝时无推理调用，也不宣称完成；已经分配的 Slurm 时间仍计成本。

2026-10-16的[函数指纹修正](正式评测指纹修正记录.md)将 code SHA 改为显式marshal格式2，避免默认格式4受引用计数/GC影响而误报代码变化；当前版本为 `formal-evaluation-explicit-archive-resume-adapter-v2-marshal2`。仍严格核对原函数恢复及不可变源码，推理逻辑不变；指纹仅在同Python环境内比较。

实现验收使用CPU合成数据；另有一次服务器Python 3.11无模型指纹探针。未加载真实权重、读取封存值或提交真实下游GPU任务。首次真实评测仍由root按既定前置条件登记。完整日志与调用ID继续纳入后续GPU成本核对。
