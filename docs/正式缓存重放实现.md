# 正式独立磁盘缓存操作成本重放

`scripts/replay_formal_cache_cost.py` 是只读标准库分析器。它只读取项目内 SHA 绑定的非权重 JSON/JSONL，不导入模型、不联网、不读初态值、不提交作业。它实现[成本归属草案](正式成本归属接口草案.md)，不改变被冻结的训练协议。存在这个入口不代表72组训练已完成。

```text
python scripts/replay_formal_cache_cost.py --project-root F:/CTI-VLA --registration configs/experiments/formal_main_v2.json --evidence results/formal_main_v2/cache_replay_evidence.json
```

默认输出到 stdout。可指定 `--output 新文件.json`；禁止覆盖已有产物。入口拒绝权重目录、封存目录、初态目录和 `panel.json`，包括伪装成JSON的路径；SHA在读取前及结束时复核。

## 证据契约

每个 `ref` 都是 `{"path":"项目相对路径","sha256":"原始文件字节SHA"}`。`registration_sha256` 使用排序、紧凑JSON的内容签名，不能与文件SHA混淆。

```json
{
  "schema": "formal_main_v2",
  "kind": "cache_replay_evidence",
  "registration_sha256": "登记内容签名",
  "supervisor_state": {"path": ".../supervisor_snapshot.json", "sha256": "..."},
  "accounting": {"path": ".../accounting_snapshot.json", "sha256": "..."},
  "root_cost_inventory": {"path": ".../final_cost_inventory.json", "sha256": "..."},
  "suites": {
    "libero_10": {"windows": {"path": "configs/manifests/formal_main_v2/libero_10/windows.json", "sha256": "..."}, "protocol": {"path": "configs/manifests/formal_main_v2/libero_10/protocol.json", "sha256": "..."}}
  },
  "training": [{
    "suite": "libero_10", "visual_tokens": 128, "seed": 17, "arm": "A",
    "report": {"path": ".../A/training_report.json", "sha256": "..."},
    "receipt": {"path": ".../A/deployment_receipt.json", "sha256": "..."},
    "training_order": {"path": ".../A/training_order.json", "sha256": "..."},
    "cost_events": [{"path": ".../A/attempts/ATTEMPT/cost_events.jsonl", "sha256": "..."}]
  }],
  "cache_jobs": [{
    "job_id": "3005060", "namespace_sha256": "缓存身份内容签名",
    "cache_events": [{"path": ".../cache_events/JOB_UUID.jsonl", "sha256": "..."}],
    "job_receipt": {"path": ".../job_receipts/JOB.json", "sha256": "..."},
    "root_review": {"path": ".../segment_reviews/JOB.json", "sha256": "..."},
    "verified_pull": {"path": ".../pulls/PULL/receipt.json", "sha256": "..."}
  }],
  "target_hardware_job_by_suite": {}
}
```

最终须有4套件、72个实例和全部attempt日志；未完成阶段可先提供`progress_report.json`检查已知身份和访问流，但始终返回`pending_evidence`。原始文件不修复、不截尾。每个训练job最多有一个A和一个B attempt，符合被冻结的单次CLI调用。根对话若采用新调度方式，应另审接口，不能静默猜测。

`root_cost_inventory`沿用统计入口的 `schema=formal_main_v2`、`kind=final_cost_inventory`、`issued_by=root`、`complete=true`、`registration_sha256`、`job_ids`，增加：

- `cache_job_ids`：本清单纳入缓存证据的全部训练及已验收准备job。
- `evidence_sha256`：逐项目相对路径绑定全部报告、收据、顺序、attempt/cache日志、root review、verified pull、监督/账单快照、四套件windows/protocol及可选硬件证据。它是root对完整归档的关闭声明，不能由分析器自行签发。

总账必须覆盖监督快照的所有正式作业，包括失败和CPU作业；每个job只计一次 `elapsed_seconds × gpus`。缓存估计永远不叠加到总账。`verified_pull`必须是稳定终态的原始非权重回存收据，绑定实际字节数、SHA及服务器路径；回存清单出现但证据清单遗漏的attempt/cache日志会阻止完成。训练报告、部署收据和顺序也必须在verified pull中找到同SHA。

准备作业只接受已通过root验收且Slurm成功的同namespace来源。其cache job条目另附 `acceptance_complete` ref；root review、模型指纹、作业身份、回存与账单必须一致。准备的黑图publication能校准冷黑图大小和生成，但不被写成训练吞吐，也不重复加入实际账单。

历史验收review只直接绑定verified pull、job receipt和acceptance complete，而非每条cache文件。实现接受完整的 `root review → verified pull → cache SHA/bytes/服务器路径` 链；如review同时存在cache直接条目，则也必须一致。不要求修改历史writer或历史收据。

## 计数与计时分开

每arm独立冷128GiB磁盘、2条窗口RAM、额外常驻黑图引用；黑图在磁盘被pin且占容量。每500步进程边界清RAM和黑图引用，保留磁盘。首次先validation0，随后每段4000次训练窗口和一次完整validation，共40000训练使用与11次验证。RAM hit不触碰磁盘LRU；磁盘hit更新LRU，发布时按LRU驱逐非黑图。不会在每次验证时额外清RAM。

实际共享A/B同段共用provider，黑图只查一次；这不改变独立arm各自冷启动的反事实定义。A使用现有完整provider，仍生成未来目标，不假设一个未运行过的A专用producer。

大小只取同hashed key的实际publication或已记录的committed eviction bytes。缺失或冲突时该arm计数为`unknown_sizes`，不使用全局均值、别的窗口或资源规划中的代理大小。实际请求顺序通过40000顺序、逐sample start/end、完整validation及cache事件交叉核对。

每个已完成`cache_hit/cache_publish`保留seconds、原文件SHA、行号、namespace/key、job及已证实硬件信息。所有尖峰保留。publish已经包含生成、锁等待和磁盘工作，feature/current/teacher/future内部phase不重复加入。按同key、同operation、同namespace和同完整硬件身份汇总全部观测的均值和min/max；未观测操作保留unknown，不用另一种操作补齐。

输出用一个共享`observation_index`存journal SHA和全部已完成操作行号。完整硬件身份可用的校准组只存一份均值/min/max与source索引；缺硬件身份的原始秒值仍在这些行中，不能进入可归属计时。每arm不重复复制原始秒值、sources或每key操作列表，而保留汇总计数、覆盖率、未知数量和操作/请求/决策流SHA；按原始日志可完整复算。这样索引规模随实际日志行数增长，不再乘72。大小证据也用原journal计数和SHA归档，不复制每次publication到每arm。

Slurm allocation只能证明诸如 `gres/gpu:l40=1` 的硬件类别及节点。可选 `hardware_record` ref必须来自该job自身的verified pull；已有验收 `resume_acceptance.json` 的 `gpu_name/torch_version/cuda_version` 只属于验收job，不继承给训练job。完整计时校准身份还要求该job已有metadata中的 `driver_version/device_uuid`。缺失时保留已知字段，反事实耗时为 `unknown_hardware_identity`；计数不受影响。`target_hardware_job_by_suite`如填写，必须指向同套件已证据化job。未知不得填零，不为计费新增GPU测量。将来若已有只读环境归档可补证，由root提供其原始SHA和来源，再审计使用。

## 失败和输出

SQLite提交与日志写入不是同一事务。开放miss、生成后无publish或末行截断保留unknown，不用后续hit补造publication；不声称重建真实故障后的共享磁盘历史。中间JSON损坏、错误身份、错误请求序列等拒绝。末行即便是完整JSON但无换行，也不当成已提交事件。

`pending_evidence`表示完整自然日志或root关闭声明尚缺，不能形成主实验完成信号。完整证据核验后可返回`completed_estimate_with_limitations`：它允许明确的大小、计时或硬件unknown，不代表每个反事实费用都已识别。逐arm输出精确计数或缺失/冲突大小数量与列表SHA、请求/决策流SHA、校准覆盖率、只覆盖部分操作的subtotal与完整总数（不齐则null）。报告名称固定为“独立磁盘缓存操作成本估计”，不声称完整独立训练GPU账单。

合成测试覆盖RAM/LRU差异、跨段重启、pin容量、同key校准、尖峰、缺字段、截断、失败事务、身份隔离与总账去重。单arm解析器实际读取完整40000样本writer形状日志；72实例入口测试只替代重复日志展开层，保留真实登记/报告/收据/回存/root链、40000调度重放与完成判据，避免生成GB级重复fixture。实际首1000通过正式analyze入口做只读pending检查，不作为完成72组的替代证据。
