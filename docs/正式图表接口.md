# 正式图表接口

`scripts/render_formal_results.py` 只排版 `scripts/analyze_formal.py` 的严格分析结果，不读取权重、上游原始引用或封存状态，不运行实验、不重算统计。新增工具在本地 CPU 使用已有 matplotlib；不修改服务器冻结环境。

```powershell
python scripts/render_formal_results.py --analysis results/formal_main_v2/analysis/summary.json --output-directory results/formal_main_v2/figures/v1
```

路径为示例，输入必须实际存在。输出目录必须是项目内**尚不存在**的新目录；旧产物不覆盖，重复排版应使用新目录。

## 输入与门槛

- 接受分析版本 `formal-main-v2-analysis-1`，校验输出记录的分析脚本 SHA 与当前 `scripts/analyze_formal.py` 一致。历史分析需保留对应脚本版本后再排版。
- 只有 `completed_core_analysis` 可生成主图表；要求四套件、22 个部署实例、72 组训练诊断、36 组 A/B token 对照以及两种测速摘要完整。
- 正式分析为 1600 个唯一最终初态、35200 条闭环；每套件400个初态。三种子复用初态不扩大独立初态数。
- `pending`、输入不存在或完成状态缺字段时，只写 `render_receipt.json`，列明缺项，无主图/主表。协议冲突、错误数值、重复实例、分析源码 SHA 不匹配直接拒绝。
- 不跟随 `read_evidence_sha256` 引用；原始证据审计属于严格分析器。渲染器校验消费字段与协议，不能替代原始收据审计。
- 新缓存结果须具有`formal-cache-evidence-integration-v1`接入标记、相同登记、重放源码SHA及原始清单/账单/root清单的分析读取绑定；不能将独立completed摘要手工拼接进分析输出。渲染器只检查上游已重算的结果，不打开原始日志。旧版明确pending摘要继续可读。

## 产物

- `formal_results.pdf`：可独立分享的科研图表册；各页另存 PNG。
- `main_success.md` / `main_success.png`：Spatial/Object/Goal/Long及四套件等权均值，主预算 Dense512、Uniform128、A128、B128。
- `success_latency.png`：四套件的256/128/64预算成功率—完整O2A median曲线；同时显示全部A/B种子点。`plot_coordinates.json` 保留原始精度坐标及输入SHA。
- `success_all_instances.md`、`success_families.md`、`paired_gains.md`：全部实例、全部预算的成功率均值/SD/区间及各套件/预算/seed的B−A配对差值；不挑最好种子。
- `latency.md`：全部实例完整O2A的median/p95/mean及三种子等权均值/SD。
- `components_<suite>.md`：独立分项计时，每实例/分项的host及CUDA-stream median/p95/mean。图表册使用已报告分项均值，Markdown保留全部字段。
- `action_memory.md`、`token_overlap.md`：选中checkpoint的动作误差、训练峰值allocated显存、A/B集合重合率。
- `latency_ratios.md`：直接复制已分析的Dense/剪枝median、p95及mean比值，不把token减少当加速，也不把延迟比值称为训练成本效率。
- `cost.md`、`cost_jobs.md`：实际Slurm总成本、分阶段成本、全部作业（含失败/重试）、缓存证据状态与范围限制。账单逐条保留于Markdown，不额外合计或与分项耗时相加。
- 缓存证据closed时新增`cache_operation_counts.md`和`cache_operation_cost.md`：保留72组独立磁盘操作计数、覆盖/未知数量、只覆盖已校准操作的均值subtotal与经验min/max、完整操作均值（不齐为unknown）及未知原因。缺少大小时计数也显示unknown；不能借全局均值或0补齐。这两张详细表不挤入主成功率—延迟图。
- `README.md`：索引、统计口径和限制；`render_receipt.json`：输入文件SHA、分析版本/源码SHA、渲染器版本/源码SHA、matplotlib版本及全部产物SHA/大小。收据自身不进入自引用哈希列表。

## 统计和未完成项

成功率及配对增益区间照抄上游：10000次、按任务分层的初态cluster bootstrap、95% percentile CI；同一初态携带三个训练种子。区间以既定40任务和三个种子为条件，不是任务/种子总体推断；跨零不表示等价。SD是三个训练种子的样本SD（ddof=1），不是CI。

延迟族均值来自三种子各自median/p95/mean的等权均值，不能解释为合并调用的分位数。该分析未提供延迟CI。完整O2A不含分项hook；分项来自独立instrumented pass，host与stream时间重叠，不累加为完整延迟。

`standalone_cache_cost`可为旧版`pending_real_training_logs`、原始证据未齐的`pending_evidence`，或完整重放的`completed_estimate_with_limitations`。前两者的README/成本表/收据保留具体缺项；后者保留全部unknown、覆盖率与范围限制，收据状态为`rendered_core_results_cache_estimate_with_limitations`。closed只表示证据核验结束，不代表每项独立操作耗时已知。覆盖部分的subtotal不能显示为完整费用，经验min/max不是置信区间。实际Slurm总账、共享增量诊断与独立磁盘操作反事实分别呈现，不相加。

收据复制`core_results_complete`、`cache_evidence_complete`、`independent_cache_operations_fully_identified`和`delivery_status`。**`main_experiment_delivery_complete`始终为false**，并说明完整独立训练GPU账单及论文最终交付仍需root核验。即使全部已定义磁盘操作均可校准，也不代表模型加载、RAM/wrapper、计算或反事实竞争等完整独立运行费用已识别。本轮登记的显存指标为训练峰值，缺失的组单独显示pending；不把未登记的部署显存或成本回本分析变成新增门槛。

## 合成测试

```powershell
python -m pytest tests/test_formal_render.py -q
```

测试只使用明确的 `synthetic: true` 合成摘要。渲染合成输入必须显式传 `--synthetic`，所有PNG/PDF页与Markdown均标明 **SYNTHETIC — NOT EXPERIMENTAL RESULTS**，文件名以 `synthetic_` 开头，收据 `production_results=false`。真实/合成标识混用拒绝。测试产物不能用作已测实验结果。
