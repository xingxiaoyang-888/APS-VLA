# 正式测速接口

`scripts/profile_formal.py` 仅使用开发初态。套件、基座、部署身份和方法列表沿用 `formal_main_v2`；CLI 不读取最终状态，也不提交作业。

三种命令：`collect`、`full`、`components`。共同参数：

```text
python scripts/profile_formal.py COMMAND \
  --registration configs/experiments/formal_main_v2.json \
  --execution-manifest /PROJECT/results/.../development_execution.json \
  --development-panel /PROJECT/configs/manifests/formal_main_v2/SUITE/initial_states/development.json \
  --protocol /PROJECT/configs/manifests/formal_main_v2/SUITE/protocol.json \
  --windows /PROJECT/configs/manifests/formal_main_v2/SUITE/windows.json \
  --input-acceptance /PROJECT/results/.../input_acceptance.json \
  --asset-manifest /PROJECT/configs/assets/openvla_oft_libero_SUITE.json \
  --checkpoint /REGISTERED_CAPACITY_MODEL_DIRECTORY \
  --cache-directory /PROJECT/.cache/formal_profile \
  --project-root /PROJECT --output /PROJECT/results/.../NEW_OUTPUT \
  --uncontended-gpu
```

`execution-manifest` 使用正式闭环执行器的 `evaluation_execution` schema，必须 `split=development`。`collect` 清单只含 dense；`full/components` 必须按 `formal_trials.expected_method_ids()` 列出完整22实例。每个训练实例须提供相同的 `identity/checkpoint/receipt/pair_config/f01_report`。程序核验注册路径、配置、F00/F01原始调用日志、suite128/seed17的F03恢复验收、冻结源哈希及选中checkpoint，不接受pilot权重。F03文件为F00同目录的 `resume_acceptance.json/f03_calls.jsonl`。

`collect` 另指定 `--oft-source`、`--libero-source`、`--libero-config`。每任务最低开发source index，以固定dense、env seed0、runtime seed17、wait10、chunk8完成一条轨迹；环境代理在每个实际控制动作之前复制原始观测。轨迹结束后取 `0,(N-1)//2,N-1`，不足3个则失败。每任务保存3个原始NPZ、全部控制步观测哈希和实际dense动作日志。采集成本单计，不作为新增成功率trial。

`full/components` 另指定 `--panel .../collection/panel.json` 和 `--global-freeze .../global_final_freeze.json`。全局矩阵须完整88实例及4套件开发完成收据；当前22身份逐项与成功率评测冻结身份相同。无需最终release或最终初态文件。两pass使用不同新输出目录；每pass各14300调用，50次预热/实例＋20轮×30观测/实例。seed20261016打乱基础22方法顺序，每轮左移一位，观测顺序始终相同。

主pass从已就绪raw数组＋指令计时至CPU可执行8×7动作就绪，前后CUDA同步；涵盖预处理、vision、DIE条件与Top-k、packing、LLM/动作头和后处理。主pass不装forward hooks，无教师/未来头/跨调用特征或语言cache。模型、NPZ读取、方法切换、日志及遥测在单次边界之外，但仍计入Slurm总成本。只允许一张无其他compute进程的L40，每方法块前后检查GPU UUID与竞争进程。

组件pass独立插桩：`preprocess/vision/condition_selection/packing/llm_action/postprocess`，另列未归类host开销。packing与LLM边界通过共享forward的backbone pre-hook观察，不复制packing实现；主pass不安装该hook。host区间和CUDA stream事件重叠，不能相加；stream事件包含CPU发射间隙，不能称纯kernel耗时。组件pass总时间不替代主pass。

每个计时输出包含 `attempt.json/config.json/calls.jsonl/measurements.json/summary.json`。原始journal保留全部预热、尖峰、异常与未完成调用；失败输出不可覆盖，不自动重试。`analyze_formal_profile(directory, registration)` 从全部raw calls复建median/p95/mean、同批dense配对速度比和三seed等权均值/样本标准差。显式 `method_ids/observation_ids` 固定统计顺序，排序JSON往返不会改变结果。

`--prepare-only` 只核对配置/面板/身份，不载入模型或调用GPU，报告 `weights_validated=false`。真实运行只能由root在Slurm中启动；权重留服务器，非权重产物回存CTI-VLA，Slurm GPU秒另行对账，包括全部加载、采集、两个测速pass及失败尝试。
