# 正式下游产物复核

`scripts/review_formal_downstream.py` 是 E04 的本地 root 审计 producer。它读取终态作业的 SHA 回存证据，不联网、不提交或取消作业，不加载 checkpoint，不打开封存初态及 final 输出中的状态值 panel。新增实现和 CPU 合成测试不代表真实实验已经通过。

默认仅复核并打印简短结果，不写收据。root 已完成监督状态与终态账单核对、完整非权重回存后，可执行：

```powershell
python -B scripts/review_formal_downstream.py --job-id <登记ID> --pull-receipt results/formal_main_v2/pulls/<回存批次>/receipt.json
```

只有加上 `--write --root-review --output results/formal_main_v2/downstream_reviews/<新名称>.json` 才写新收据。输出必须不存在；任何校验失败均不生成 `passed`。工具使用既有监督锁，但不刷新服务器状态，不修改监督状态。根对话负责实际调用。

共同校验包括登记 job、终态和完整 Slurm 分配成本、原 invocation、173 冻结文件、E04/adapter/wrapper SHA、所有运行输入、已完成 5000 更新的选择器收据、稳定回存前后清单、逐文件 SHA/字节数，以及 wrapper 归档的该 job 唯一 adapter 收据和完整 journal。审计候选在写盘前还要通过原 E04 `require_root_review`。Python 函数字节码 hash 只在同一服务器 journal 内交叉核对；源码身份用完整冻结文件 SHA，不在不同 Python 版本上伪造相同 marshal hash。

| stage | 重算依据 |
| --- | --- |
| development / final | 流式检查每个 start/result、状态和方法身份、每个硬剪枝 chunk、实际执行动作、配对初始观测、成功/失败终态和所有未完成尝试；复用原 summary 函数重算逐任务及 A/B 配对，要求保存报告逐项一致。 |
| collect | 固定每任务最小开发 source index 的 10 条轨迹；原 collection ledger 与轨迹收据一致，原 panel loader 验证真实首/中/末 30 个 NPZ 的数组、时间位置、schema 与哈希。采集不增加成功率样本。 |
| full / components | 原 `analyze_formal_profile` 和 journal validator 重算全部 14300 次调用（1100 预热＋13200 正式调用）、22 方法、30 原始观测、20 轮顺序及统计；另核输入任务/阶段、方法/checkpoint、无缓存/未来头和 full 无分项 hooks。分项计时不替代完整延迟。 |

final 先重验完整 72 选择器＋16 参考、四套件开发审计、global freeze 和 root release，只读最终索引元数据核对 trial 身份。实际状态字节是否符合登记值由原冻结服务器 loader 验证；本地审计明确记录没有读取状态值，绝不把不读状态值表述成独立重读验收。

`status=passed` 表示证据可以完整复核；`scientific_complete` 单独记录。分段闭环、失败后保留的合法未完成 start、可重建的部分 collect 都不会被报告为科学完成。所有已登记前序尝试和本次作业分配时间均保留，未知尝试调用量维持未知，不能填零。

续跑逐级核对所有历史 root review 与当时的 pull SHA。只有同目录的 trial ledger 和报告允许按原前缀及重算规则增长；旧 adapter 归档、job receipt、Slurm 日志等必须保持原 SHA，不能用一次新的回存掩盖历史改写。

当前严格边界：缺 ledger、缺 adapter 收据、JSON 尾不完整或缺 LF、保存报告落后于原始日志、回存不完整均拒绝生成审计，不补写历史字节。未完成 full/components 暂需单独人工取证，当前 producer 不生成通过收据。若 collect 已写 panel 后异常、或已完成轨迹缺少可验证收据，也交 root 作有界诊断。作业在建立这些证据前退出时不能据此自动重跑。任何失败日志与 Slurm 费用仍须保留。
