# 正式评测函数指纹修正

2026-10-16，固定案例CPU合成整链测试在第三个套件的适配器恢复复核中失败。函数、代码对象及源文件均未变化，但默认 `marshal.dumps(code)` 的序列化字节随临时引用与垃圾回收变化，原严格SHA比较因此误报。失败发生在合成测试，当前正式训练与真实下游GPU作业均未受此问题影响。

实现者和独立审阅者分别复现：Python 3.10中，重复私有导入后GC、或仅增加 `co_consts` 等属性的引用，均可改变默认格式4的哈希。root在服务器Python 3.11.7上做无模型的AST编译探针，也观察到同一代码对象的格式4哈希变化；显式格式2保持稳定。函数未执行，未加载权重或读取封存初态，没有新增Slurm/GPU作业。

修正仅将适配器函数指纹改为 `SHA256(marshal.dumps(code, 2))`，标记版本 `formal-evaluation-explicit-archive-resume-adapter-v2-marshal2`，并更新下游controller和wrapper允许的适配器SHA。仍保留绑定恢复前后严格相等和全部173源文件哈希校验；代码/常量篡改必须继续失败。该指纹只用于同一Python运行环境内比较，跨主机源码身份仍由文件SHA确定。

旧适配器SHA为 `260f1525455ef00e74edc1b53f913a7fc955d06c5f4905794e640c1ff7798e5e`；新SHA为 `b54dc0d87cbc10c639b0cf59475011f7a68809999862c14ebf02393e96764acd`。新controller和wrapper身份、诊断原字节及最终测试结果记录于[工程修正收据](../results/formal_main_v2/repairs/code_fingerprint_marshal2_v1/repair.json)。历史审计不重写，旧适配器没有产生需迁移的正式开发/最终/测速作业。

训练损失、数据、门控、packing、策略、环境、计时边界及最终release条件不变。权重仍仅存服务器；合成case日志不得混入正式trial或GPU账单。
