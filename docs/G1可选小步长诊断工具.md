# G1 可选小步长诊断工具

2026-10-14。状态：**工具已审计；完整 G1/D4 科学审阅后已激活，GPU 状态见 [实验进度](实验进度.md)**。固定注册为 [`spatial_g1_step_diagnostic_v1.json`](../configs/manifests/spatial_g1_step_diagnostic_v1.json)，脚本为 [`run_teacher_step_diagnostic.py`](../scripts/run_teacher_step_diagnostic.py)。这是主 G1 的补充诊断，不能替代主结果或自动开启 G2。

注册的 3 个 train 观测分别来自 3 个 episode/task，覆盖 early/middle/late。选择由父 teacher12 成员和 seed717 重建，不能按结果换样。原主链为 512→256→128→64；补充链为 512→384→256→192→128→96→64。两链使用同一 `run_exact_selection`、seed517、实际删除标签、相机等额预算和原索引平分规则。输出所有方法在 256/128/64 的原始结果、补充结果和配对误差差值；静态、均匀与 random17/23/41 对照保留。

正式执行前必须有完整 G1 的 90/12 observation/journal、权重最终验证和 D4 完成报告；它们的文件哈希必须一致。3 个原始 exact 结果会从原始 action journal 重算。模型、packing、输入、数据解析与诊断/采样源码必须和 G1 producer 相同；真实新输入、projected features 与旧日志逐字节比对，full action 与旧日志在原 G1 noise tolerance 内匹配。恢复时也重算新日志、full action 差异和两链比较，不相信已有 JSON 的结论。

科学审阅者仅在完整 G1 未显示稳定的 128-token 教师优势时，另行写激活收据。工具不创建有效收据。收据要求如下（尖括号是占位符，不是批准）：

```json
{
  "schema_version": 1,
  "decision": "activate_optional_step_diagnostic",
  "main_g1_scientific_decision": "no_go",
  "registration_sha256": "<注册文件SHA256，不含sha256:前缀>",
  "g1_config_sha256": "<G1规范JSON内容SHA256>",
  "g1_finalization_sha256": "<G1最终验证文件SHA256>",
  "d4_summary_sha256": "<D4 summary文件SHA256>",
  "reviewed_by": "<审阅者>",
  "reviewed_utc": "<审阅时间>",
  "review_notes": "<科学判断及证据>"
}
```

独立输出包含冻结 `config.json`、`observation_panel.json`、每观测 `queries/*.jsonl`、`observations/*.json`、调用/观测尝试成本、`summary.json` 和权重最终 `finalization.json`。每观测 fresh unique 上界 1604，所有重试合计最多 2000 次前向；失败、启动后中断都消耗上限。中断的耗时与完成状态保持 unknown/null，需结合 Slurm 账单核对。已知 callback 时间按真实长度记录；总调用耗时还涵盖预检查、载入、权重校验、数据解码和视觉编码。各子项嵌套于总时间，不能重复相加。该耗时不是部署延迟。

本地只允许：

```powershell
python scripts/run_teacher_step_diagnostic.py --prepare-only --output-directory results/g1_step_preflight
```

科学审阅批准后由 root 在服务器已有 GPU allocation 内执行下列接口，工具本身不提交作业：

```text
python <source-snapshot>/scripts/run_teacher_step_diagnostic.py
  --project-root <server-project-root>
  --output-directory <server-project-root>/results/g1_step/<independent-run>
  --g1-directory <complete-original-G1>
  --analysis-summary <complete-D4>/summary.json
  --activation-receipt <reviewed-activation.json>
  --checkpoint <immutable-server-checkpoint>
  --data-directory <spatial-RLDS-1.0.0>
  --cache-directory <server-project-root>/runtime/g1_step_cache
```

上述换行仅便于阅读，实际命令按所用 shell 连接；`PYTHONPATH` 必须指向 `<source-snapshot>/src`，工具会拒绝从其他安装目录导入 CTI。`--project-root` 必须包含源码快照；output/cache 是主项目子目录，不能落入独立源码快照、原 G1 或权重目录。默认项目根仅适用于本地 prepare。HF 缓存环境先于任何 Transformers/HF 导入设置。`--observation-limit 1..3` 只限制当前调用处理几个未完成的冻结观测，不改变面板或累计上限；缺少最终权重校验仍不算完成。
