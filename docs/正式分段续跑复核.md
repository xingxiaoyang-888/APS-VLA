# 正式训练分段续跑复核

入口为 `scripts/review_formal_segment.py`，由 root 在已登记训练作业终态、非权重结果完成 SHA 回存后运行。它不提交作业，不反序列化权重，不读取封存初态；默认只做本地复核并输出服务器恢复文件检查清单。

```powershell
python scripts/review_formal_segment.py --job-id 已登记终态作业号 --source-inventory results/formal_main_v2/source/formal_main_v2_run_564be0995e.json --pull-receipt 本次已验证回存收据 --verify-server-resume
```

显式 `--verify-server-resume` 仅在服务器以 CPU 哈希本配置 A/B 的两个 `resume.pt`，不下载或加载权重。已开始的训练臂必须存在与进度收据相同的恢复文件；缺失不能视为从头开始。全部通过后写入不可变的 `training/segment_reviews/{job_id}.json`。AdamW、RNG、样本游标及候选记录的内容仍由冻结训练入口在恢复时再次检查。

复核绑定登记、源快照、配置、数据清单、工程验收、调用参数、终态账单、回存清单、训练日志与逐窗口验证；独立重算任务等权动作误差、选模规则、5000 步退火、样本顺序和预算数量。各臂 update0 的硬剪枝输出和初始化须一致。失败、未提交更新及重放成本保留，不截断原始日志。

- A/B 都到当前共同边界：只允许推进到下一个 500 步边界。
- A/B 进度不齐：只允许续完当前边界，不跳到下一段。
- 两臂都到 5000：验证完整训练和部署收据，进入开发评测，不增加更新。
- 最新作业失败：先保留终态日志并定位、登记有界修正；不能用成功段的复核收据掩盖失败。

此检查补足旧提交入口对“不齐边界”和“恢复文件缺失”的保护不足，未改变正在运行的冻结源码、损失或调度。`formal_supervisor.py` 尚未自动消费该收据，root 必须先通过本检查，再按 `allowed_next_segment_end` 提交。只运行合成测试不等于真实段已验收。
