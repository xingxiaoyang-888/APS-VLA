# 正式执行清单接口

`scripts/formal_execution_manifests.py` 不提交作业、不修改冻结的模型/训练/评测源码。本地命令只读非权重资料；仅显式服务器 `checkpoint-inventory` 命令读取登记的 72 个 `best.pt` 进行哈希。所有命令均不读取 `sealed_final.json`。当前工程验收与正式训练进度由监督状态记录；以下命令不是已完成实验的证明。

开发清单要求本套件 root 审核通过的 F00/F01/F03、原始验收日志及完成标记。学习方法还要求对应 A/B 两臂完整 5000 更新、全部 11 次选模记录、匹配初始化/数据顺序、最终部署收据和服务器完成收据；工程 probe 不满足这些条件。清单中的 `checkpoint` 仅记录登记的服务器路径，服务器执行入口仍需实际读取并核验权重 SHA。

```powershell
python scripts/formal_execution_manifests.py development --suite libero_10 --methods dense uniform128 A128_seed17 B128_seed17 --source-inventory results/formal_main_v2/source/<已冻结清单>.json --output results/formal_main_v2/execution/libero_10_dev_k128_seed17.json
```

可单独生成基线或已完成配对的开发清单；省略 `--methods` 要求本套件全部 22 个身份齐备。输出伴随 `.evidence.json`，绑定全部配置/验收/训练文件及开发面板 SHA，默认不开放最终集。

全局冻结使用一个显式开发结果目录索引；同一套件可列多个互不重叠的方法输出目录，每个方法必须完整覆盖原 100 初态。索引格式：

```json
{"schema":"formal_main_v2","kind":"development_output_index","suites":{"libero_10":["results/formal_main_v2/libero_10/development/all22"],"libero_spatial":["results/formal_main_v2/libero_spatial/development/all22"],"libero_object":["results/formal_main_v2/libero_object/development/all22"],"libero_goal":["results/formal_main_v2/libero_goal/development/all22"]}}
```

```powershell
python scripts/formal_execution_manifests.py freeze --source-inventory results/formal_main_v2/source/<已冻结清单>.json --development-index results/formal_main_v2/development_index.json --checkpoint-inventory results/formal_main_v2/checkpoints/<服务端核查收据>.json --output-directory results/formal_main_v2/final_freeze
python scripts/formal_execution_manifests.py release --directory results/formal_main_v2/final_freeze
```

`freeze` 必须集齐 72 个正式选择器、16 个参考身份及四套件各 22×100 条开发原始 start/result 账本，逐套件重建 `development_completion`；还要求一小时内生成的服务器权重核查收据，72 条登记路径/存在性/实际 SHA 必须逐一匹配选择后的 checkpoint。缺项、过期或不一致均拒绝全局冻结。它仅读最终 `final_registry.json` 中的索引与哈希，验证与开发面板隔离，不读取封存状态值。每套件仍只有 100 个独立开发初态，三个训练种子不是新增初态。

权重核查由 root 在服务器 CPU 上调用；不分配 GPU、不提交 Slurm。该脚本只读取登记配置派生的 `H/checkpoints/formal_main_v2/{suite}/k{budget}/seed{seed}/{A|B}/best.pt`，不枚举或读取工程 probe、resume、其他项目权重。全部哈希、字节数和读取前后 stat 稳定性，以及注册/源码清单/检查器 SHA 都写入非权重 JSON，再回存项目。示例（服务器，需使用与本地同一检查器脚本）：

```bash
python scripts/formal_execution_manifests.py --project-root /ssdfs/datahome/u15016/XXY_CVPR/CTI-VLA checkpoint-inventory --source-inventory results/formal_main_v2/source/<已冻结清单>.json --output results/formal_main_v2/checkpoints/<新的服务端核查收据>.json
```

检查器在本地调用会拒绝访问权重；服务器缺少任何登记 checkpoint 时报告完整缺项，不生成“通过”收据。一小时仅为冻结前文件存在性核查的新鲜度约束，不改变科学实验设置；最终服务器执行仍再次核验实际权重。

上述 `release` 命令只重新核对全部冻结证据。root 决定开放最终评测时，才显式添加 `--release`：

```powershell
python scripts/formal_execution_manifests.py release --directory results/formal_main_v2/final_freeze --release
```

此时生成 `root_release.json` 和四份 `final_execution/*.json`，仍不读取封存值。后续服务器最终评测入口核验 release 文件 SHA、全部冻结身份及对应最终清单后，才读取登记的最终状态。全部输出不可覆盖为不同内容；证据变化必须重新审核并使用新冻结目录。
