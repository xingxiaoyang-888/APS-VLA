# 正式主实验资源估算

入口：`scripts/estimate_formal_resources.py`。只读已回存的 JSON/JSONL；不加载模型、缓存 tensor 或初态，不联网、不提交作业、不改变冻结训练源码。没有 Long128 seed17 的 A/B 各至少 500 次正式更新及完整证据时，输出 `pending`，不生成训练预算。验收作业和旧小实验不能替代正式训练吞吐。

```powershell
python scripts/estimate_formal_resources.py --registration configs/experiments/formal_main_v2.json --evidence results/formal_main_v2/resource_evidence.json --output results/formal_main_v2/resource_estimate_v1.json
```

输出须为本项目内尚不存在的 JSON；新版估算使用新文件名，保留旧结果。证据清单暂不存在时也可运行，得到明确的缺项记录。

终态的 `seconds` 与 `attempt_elapsed_seconds` 是两次有序取时：冻结训练器先取训练时长，再收集内存统计，最后记录事件时间。三种退出状态均要求“前一事件时间≤seconds≤终态事件时间”；不要求两次取时在固定毫秒范围内相等。延迟单独记录，归入既有Slurm总账的arm外时间；累计终态跨度仍不得超出实际分配。2026-10-16修正通过root和独立审计各86项测试、真实1000步证据复算，见[复核收据](../results/formal_main_v2/preflight/resource_terminal_clock_cpu_review.json)；首段原账单与规划值不变。

`acceptance_cache_preparation` **可省略**。它解决「验收已生成黑图，训练只有黑图磁盘命中」的情况；不能用任意历史缓存准备日志代替。每项必须同时绑定已登记 Long 验收、成功终态单 GPU 账单和 stage receipt、`passed` 的 root 验收、root 验收已绑定的 verified pull。pull 中的文件 SHA/大小/作业与服务器目录必须一致。整份准备日志须属于与参考训练**完全相同**的 `cache_identity_sha256`，窗口与基座相同，并早于训练缓存日志。

仅提取完整 `shared:black-image` 的 miss→generate→publish，保留记录大小、发布耗时、原始记录 SHA 和验收/回存来源。普通窗口生成、教师、future 和工程验收阶段一律不进入训练吞吐或普通记录成本。黑图生成计时已嵌套在发布耗时内，不相加；早先验收分配已在实际 Slurm 总账中，不重复计费，也不视为免费。没有训练 black publication 时，冷缓存场景使用这份已测准备成本；实际训练命中仍使用训练日志的 hit 耗时。A/B500 与完整 165 窗口验证门槛完全不变。

## 已测量与估算的边界

- **唯一实际总账**：登记的 Slurm `elapsed_seconds × gpus`，每个 job 只计一次，含失败、验收、训练等。共享 A/B 作业不能各复制一份账单。阶段、缓存、未来头耗时仅作诊断，不能再加到总账。
- **训练实测**：全部完整 batch8 更新及两次以上完整 165 窗口验证，报告含缓存 wall time、扣除嵌套缓存操作后的时间、每秒更新数、保存耗时、条目大小、缓存请求/命中/淘汰及 A 触发的未来生成时间。保留全部完整区间和尖峰；失败的不完整更新不冒充完整吞吐样本，其分配和残余耗时保留。
- **缓存耗时**：`cache_publish.seconds` 已包含特征生成、教师和未来表征、磁盘发布等，不能再加 `feature_generate_end` 及其分项；普通磁盘命中有独立实测耗时。黑图的大小和冷发布成本可来自上述严格绑定的同 namespace 验收准备，输出 `black_cache_calibration` 单列其来源。首次无黑图磁盘命中时，使用普通记录命中区间作显式代理，不设为免费。
- **作业开销**：Slurm wall time 减本作业全部 A/B attempt 区间。包括模型加载、输入/源码核验、恢复优化器、进程与作业开销。现有日志没有模型加载独立计时，脚本不会虚构该单项。验证结束事件比其计时器多出的区间用于候选 checkpoint/JSON 写出；每 50 步的 resume 保存单列。

## 72 组训练的条件场景

这是从头完成 72×5000 的规划场景，**不是剩余成本**，不能加到已发生训练账单上。A/B 使用各自实测区间，不用小实验时间直接乘倍数。每组 40000 次训练窗口访问、11 次完整 validation、102 次 resume 写入；尚未测到的最终 `best.pt`/receipt 导出以一次 resume 写入作为明确代理。

使用实际四套件全池清单及正式私有 Python RNG 采样算法，重放 128 GiB 磁盘 LRU、2 条 RAM LRU 和固定黑图记录。RAM 命中不刷新磁盘 LRU。已见窗口使用实测条目大小；其他窗口用已见最小值和最大值×1.25 两种大小场景。实际缓存是否预热由原始日志反映；预测场景假设新 namespace 冷启动。

共享场景假设 Long128 seed17 首对前移，此后按登记清单顺序串行，每对完成 10 次「A500 然后 B500」调用后再做下一对，总 360 个成功调用。各 arm 独立场景使用独立冷缓存，各 10 次调用，共 720 个成功调用；不共享 arm、seed、预算间的缓存。该独立场景是给定缓存和顺序假设下的资源参照，**不是任意并发/故障行为的严格上界**。这些顺序和调用数是工程资源假设，后续预算/seed 的实际调度尚未登记，应按真实调度更新。

两个端点使用完整已测区间的最小/最大值；不删尖峰。额外倍率显式写入脚本 `ASSUMPTIONS` 并输出签名：其他未测套件 0.75–1.5，非 128 预算的更新 0.9–1.25、硬验证 0.5–2，作业开销 0.5–2；故障/额外恢复预留 0–15%。这些倍率是规划假设，没有概率或置信区间含义，也不是经过实测验证的上下界。结果同时输出每个端点和排序后的区间，避免缓存变化导致端点不单调时误标。

v2 另增 `training_projection.observed_mean_planning_point`，用于资源安排：各类耗时取全部完整观测的算术均值，保留尖峰，不做截尾或百分位替代；A/B 更新、验证与保存分别取均值。已见 Long key 使用实际记录大小（重复发布大小不一致时取观测最大值），未知 key 使用全部普通记录发布大小均值向上取整，黑图使用已验证发布大小均值向上取整，再运行相同完整 LRU 重放。未测套件、256/64 预算及作业开销倍率均固定为 **1.0**，即尚未验证的 Long128 代理，不代表已测全矩阵吞吐。

均值规划点分别报告共享缓存、各 arm 独立缓存的基础 GPU 小时，再单列 0% 和 15% 故障预留选项；二者不是置信区间。原最小/最大压力场景、数值端点及 v1 假设单独保留，并输出其原始假设签名；v2 总版本与均值规划假设另有签名。旧结果文件不重写。均值点同样只估完整 72 组从头训练，不能用作剩余时间；不含未测闭环和测速成本，也不替代正式独立缓存成本归属审计。

当前共享 provider 仍会在 A 缺失记录时生成未来目标，A 损失不使用它。真实生成时间和独立运行缓存成本均保留。A 触发的这部分时间不等于共享系统可省去的时间，因为 B 仍需要未来目标。仅在独立缓存场景另列「A 的训练记录可假想省去未来生成与未来变化诊断」的时间分量：保留验证诊断和原条目体积，不在主场景中扣除；该 A 专用 producer 没有运行过，不能当作实测节约。

其他三套件与 256/64 更新吞吐尚无实测时保持条件性。正式开发/最终闭环、观测采集与完整/分项测速成本没有对应实测时为 `pending_measurements`；不借用旧 Spatial 延迟。因此主实验完整资源总额仍为 `pending`。此工具不授权额外训练或为计费重跑。
