# 正式独立缓存成本归属

这是日志分析接口设计，尚未实现或产生成本数字；不授权额外训练或缓存重跑。它与[资源规划场景](正式资源估算接口.md)分开，最终用于补齐[统计入口](正式统计接口.md)的独立成本说明。

证据须包括全72组完成报告、部署收据、采样顺序、所有attempt/cache日志、四套件清单与缓存身份，以及同namespace准备作业的缓存日志、root验收、verified pull和终态账单。全部文件按字节SHA绑定，计时校准保留原文件SHA和行号，失败与不完整事务原样留存。

每组独立重放现有provider：冷启动128GiB磁盘缓存、2条RAM、不可淘汰黑图；40000次训练窗口使用、11次完整验证，每500步重启进程缓存但保留磁盘。黑图另驻内存，磁盘大小计入容量；RAM命中不刷新磁盘LRU。实际共享运行在同一段A/B之间复用provider，不在切换arm或每次验证时清RAM/黑图。只在所有相关key的大小齐全且一致时报告精确命中/生成/淘汰计数；缺项明确为未知。这是假设无故障的独立运行访问流；实际失败和重放仍保留在真实账单，不能混入该访问流。

耗时只按同namespace、同key、同硬件的实测 `cache_publish/cache_hit` 校准，保留全部观测的均值及最小—最大范围。发布耗时已包含生成及磁盘工作，不再叠加current/teacher/future分项；未出现过的反事实操作为unknown，不能用其他套件或全局均值补齐。单次观测不等于无不确定性，经验范围不是置信区间或严格上下界。

A仍按当前完整provider重放，包含它实际生成的未来目标。A触发的future时间不等于共享系统可省去的成本，因为B仍需要这些目标；本分析不假设未运行过的A专用producer。

RAM命中、部分provider包装、首次黑图前的episode/shard校验缺少独立计时；发布日志也不能分离锁等待、episode缓存和磁盘状态的反事实变化。因此交付物命名为“独立磁盘缓存操作成本估计”，不拼造成完整独立训练GPU账单。实际Slurm总账逐job只计一次，另列72组重放计数、估计、覆盖率、未知项及请求/决策流SHA。

数据库提交先于`cache_publish/cache_eviction`日志；若中途退出，事务可能已完成但未留事件。后续hit不含记录大小或内容SHA，不能据miss或hit补造publication。保留此类事务的未知状态；它不阻止其他证据充分key的无故障计数重放，也不能被用来恢复精确的故障后磁盘历史。

2026-10-16的[首段可行性复核](../results/formal_main_v2/preflight/cache_replay_feasibility_review.json)已由独立审阅及root计数复算通过。独立冷启动每arm的首500步访问流为4330次窗口请求、4165次窗口发布、165次磁盘命中，另1次黑图发布，无RAM命中/驱逐，峰值约25.88GiB。这是反事实计数；实际3005060共享作业为8660次窗口操作加1次黑图hit。完整5000步涉及的40165个窗口key当时仍有36000个缺大小证据，等待自然产生的后续日志；该复核未产生成本估计，也未增加GPU作业。

预期只读入口 `scripts/replay_formal_cache_cost.py`，由严格分析器重新计算后接入，不能接受手工填写的成本汇总。缺少所需原始日志时为 `pending_evidence`；完整证据已审计但存在上述不可识别项时为 `completed_estimate_with_limitations`，明确限制后可形成完整成本报告，不填零、不为计费重跑。
