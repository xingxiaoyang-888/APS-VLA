# Goal 查询前配对门槛：CPU候选

本包只完成源码与 CPU 工程验证，未集成生产、未提交 GPU、未接纳旧 200 条。Goal 原因仍未查明，全部后续科学开发继续 HOLD。

现有循环每个方法和初态独立 reseed、构造并关闭环境；旧观测 hash 在策略调用后产生。候选把五个原始观测组件及指令身份在首个策略调用前保存：A 形成基准，B 在调用前逐字节比较。同一试验每次查询前后检查原始输入身份和字节。它不传入未来信息、不改动作、初态、等待、chunk 或预处理。

使用既有、精确 SHA 的被动记录器私有派生：只去掉“非 t0 不记录”的过滤，并公开已写完的捕获记录供门槛检查。原 observer 的观测、RNG 和被动 simulator 不变检查保留。新 AST 仅增加捕获、校验及步骤记账调用；全部原语句、动作和 timer 顺序经反向投影校验。它要求现有动作执行兼容上下文，冻结的 173 个文件没有改动。

CPU 检验在真实冻结 Python 循环上使用合成环境和策略。66项通过；58次试验、29个配对、174次查询、986条执行动作与无门槛基线保持同样调用和动作序列，原 ledger 仅 UTC 和墙钟字段不同。错配在 B 调用前停止；输入原地变更停止后续动作；策略自己抛错仍先由原循环写 policy_error，再停止下一试验。门槛 BaseException 不被原 Exception-only handler 吞下。已执行前缀、孤立 start、原 policy_error 和单独的部分动作记录全部保留，不伪造完成行。

候选不含生产入口、Slurm脚本、调度授权或 readiness 收据。下一次最多58条的工程登记仅为草案，须独审、root整合以及真实P入口验收后另行登记。旧200始终HOLD；后续新匹配输入不能证明旧错误已修复。捕获会增加CPU和I/O耗时，不能当作推理测速，也不能证明已发生但又恢复的内部变更不存在。

所有 CPU 数组和日志原文保留在服务器；交付的分块归档与逐文件 SHA 可恢复这些合成工程证据。无权重、无封存初态值。
