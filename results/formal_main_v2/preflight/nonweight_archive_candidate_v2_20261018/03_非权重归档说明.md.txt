# 非权重归档工具

`scripts/ops/nonweight_archive.py` 是独立本地工具，只处理显式登记的 `results/` 内原始 `.jsonl` 字节。它不调用 Git、SSH、GPU，不删除或改写原件，不改已有收据，也不判断实验是否完成。终态、科学正确性及来源仍须通过已有 root 审核。本工具尚不替代现有 staging 检查；本次没有迁移真实产物。

请求清单是 `results/` 内 JSON，所有路径均为项目相对 POSIX 路径。每个原件和至少一份来源 JSON 证据必须列出精确 SHA256、bytes：

```json
{
  "schema": "cti_nonweight_archive_v1",
  "kind": "archive_request",
  "files": [{"path": "results/formal_main_v2/example/trials.jsonl", "sha256": "原始64位小写SHA", "bytes": 123}],
  "provenance": [{"path": "results/formal_main_v2/pulls/某次/receipt.json", "sha256": "来源64位小写SHA", "bytes": 456}]
}
```

清单必须由已稳定回存和审核的材料确定，不能把活跃日志当最终证据。`provenance` 校验原字节，不会替用户重做终态或科学审核。历史清单也不可覆写；同一路径增长后应使用新清单、新 snapshot 名称。

```powershell
python -B scripts/ops/nonweight_archive.py pack --project-root F:/CTI-VLA --files-list results/formal_main_v2/preflight/archive_request.json --snapshot results/formal_main_v2/nonweight_archives/v1/snapshots/指定快照.json
python -B scripts/ops/nonweight_archive.py verify --project-root F:/CTI-VLA --snapshot results/formal_main_v2/nonweight_archives/v1/snapshots/指定快照.json --snapshot-sha256 打包返回的SHA
python -B scripts/ops/nonweight_archive.py restore --project-root F:/CTI-VLA --snapshot results/formal_main_v2/nonweight_archives/v1/snapshots/指定快照.json --snapshot-sha256 打包返回的SHA
```

`pack(project, files_list, snapshot)`、`verify(project, snapshot, snapshot_sha256)`、`restore(...)` 也可直接调用；失败抛出异常，CLI 返回非零。三种操作都要求根目录存在且不经过符号链接或 junction。`verify` 不写磁盘；`pack/restore` 使用归档目录的独占 `.writer.lock`，不操作实验锁或状态。

每16MiB原始字节切一块；不解析JSON、不调整CRLF、UTF8或坏尾。每块独立gzip，mtime=0、空filename、level=6，实际压缩块必须严格小于32MiB。记录Python/zlib及实现SHA；同环境重跑可得到相同字节，不假设跨codec版本重压缩相同。空文件使用零块。

为实现跨文件分块去重，物理布局稍细化于初版设计：

- `.../v1/chunks/sha256/<压缩SHA>.gz`：不可变共享块。
- `.../v1/sha256/<原始整文件SHA>/manifest.json`：每块连续index、offset、原始/压缩SHA和bytes；整文件原SHA/bytes。
- `.../v1/snapshots/<名称>.json`：原始相对路径到对象manifest的完整映射，绑定原请求及来源证据。

恢复先验证全包：snapshot固定SHA、清单/来源、全部manifest、每个压缩块及解压块、整文件原SHA/bytes，并检查所有目标路径和已存在文件。随后暂存全部缺失文件，再次核验输入与目标后逐文件独占原子发布。路径已有相同字节时跳过，异内容拒绝；缺块、乱序、重复index、越界、SHA漂移、gzip多member/尾随/解压超量均拒绝。任何预检或暂存失败都不会恢复更早的原路径。

文件系统不提供跨多个既有目录的崩溃原子事务：最后发布期间若进程/磁盘失败，可能留下已经完整校验的文件子集，工具不会返回成功；重试按同SHA幂等继续。不会覆盖其他已有文件，也不自动回滚或删除原始记录。中断可能留 `.partial` 或未被snapshot引用的完整归档块；不得据此宣称归档完成。

原路径与归档路径均拒绝绝对路径、`..`、Windows别名/大小写冲突、符号链接/junction及项目外目标。权重、checkpoint、`test`目录、状态数组后缀和 `panel.json` 一律拒绝；任一路径段含 `init_state`、`initial_state`、`final_state`、`test_state` 或 `sealed`（不分大小写）也先拒绝，再进行任何目标stat/open/hash。这包含 `init_states_test.json` 等文件名，规则同样用于请求、来源证据、snapshot和原件。合法 `results/.../downstream/final/.../trials.jsonl` 不因包含 `final` 被禁止。此版原件仅支持JSONL，不支持NPZ、图像或任意容器；不能用压缩绕过范围限制。

GitHub上的可复现包必须包括全部块、manifest、snapshot、原请求、来源/审计依赖、工具版本与说明；只有原SHA或服务器地址不够。clone后先恢复同相对路径、SHA和bytes，再运行原审计器。现有 `results/formal_main_v2/** -text` 保持字节；仍需root另行接入实际staged blob验证、精确raw路径迁移和忽略规则。本工具没有 `git rm/add/ignore` 功能，也不扫描或迁移历史。
